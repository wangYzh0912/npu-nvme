2. 分析传统检查点的三类瓶颈：
   - 框架序列化与文件系统路径较长；
   - 同步保存阻塞训练，多线程异步路径存在控制竞争；

> 和可恢复性的基础上，缩短数据持久化路径、降低控制开销，并探索利用 NPU 计算
> 资源减少实际写入数据量。

### 2.2 异步与高频检查点策略

沿用开题报告对 CheckFreq、CheckFlow、FastPersist 和 PCcheck 的调研框架，重点比较：

- 快照与持久化两阶段设计；
- 单份与多份并发检查点；
- 训练阻塞时间；
- DRAM 快照开销；
- I/O 与训练的重叠方式。

本节结尾指出：

> 现有异步方案主要优化检查点调度，但通常仍依赖 CPU/DRAM 快照和文件系统持久化，
> 数据路径与控制路径仍存在进一步优化空间。

### 2.3 加速器直通存储与用户态 NVMe 访问

将开题报告中的 GDS、BaM、Hyperion 等内容保留为相关研究背景，同时加入当前路线：

- GPUDirect Storage 和 BaM：代表 GPU 直接或 GPU 主导的存储访问；
- SPDK：代表用户态 NVMe 驱动、轮询式 I/O 和 reactor 编程模型；
- Ascend ACL：负责 NPU HBM 与 Host/DMA buffer 的数据传输；
- 当前项目并非硬件 PCIe P2P，而是使用 ACL 与 SPDK 构建文件系统旁路的分块流水线。

重点说明现有方案在 NPU 训练检查点场景中仍缺少：

- 面向模型参数批量写入的数据布局；
- 与 NPU 运行时相结合的检查点触发方式；
- 对 SPDK qpair 所有权和并发安全的统一控制。

### 2.4 增量检查点与检查点压缩

新增本节，作为第三个创新方向的研究基础：

- 全量、差分和增量检查点的关系；
- 稀疏变化检测、Top-K 选择和量化压缩；
- CPU 侧压缩的数据搬运问题；
- 在 NPU 训练图内完成变化检测和量化的潜在优势；
- 压缩率、计算开销、误差累积和恢复链长度之间的权衡。

### 2.5 研究现状总结

用一张表总结现有工作与本课题的关系：

| 研究方向 | 主要解决问题 | 仍存在的不足 | 本课题对应工作 |
|---|---|---|---|

| 增量与压缩 | 减少数据量 | CPU 开销或误差累积 | NPU 图内 Delta |

## 3. 研究目标及研究内容

### 3.1 研究目标

将当前目标明确为三项：

1. 构建面向 Ascend NPU 的文件系统旁路检查点读写通路，实现模型参数在 HBM、
   DMA buffer 和裸 NVMe 之间的高带宽批量传输。
2. 构建单所有者、事件驱动的异步控制平面，使同步读写、后台 FaF 和元数据操作
   在统一 reactor 中安全执行，降低训练阻塞和 CPU 忙等待。
3. 探索 NPU 图内块级增量检测与 INT8 量化方案，以周期性 FULL 和 Delta 链减少
   检查点写入量。

### 3.2 研究内容

#### 3.2.1 SPDK 检查点数据面

- C 批量读写 API；
- ACL HBM↔DMA buffer；
- SPDK DMA buffer↔NVMe；
- 4 KiB 对齐、分块和有界缓冲池；
- 裸盘超级块、双元数据槽和循环检查点槽；
- Python `DirectCheckpoint` 保存、加载和磁盘工具。

#### 3.2.2 Reactor 检查点控制面

- 单 reactor 独占 SPDK qpair；
- write/read/meta 请求环；
- 异步写 FSM、异步读 FSM 和元数据 poller；
- NPU step counter 轮询和 FaF 触发；
- probe flag 持久化完成通知；
- 控制状态锁与 I/O 路径解耦。

#### 3.2.3 NPU 图内增量检查点

- 参数分块与上一版本状态；
- 图内 Delta norm；
- Top-K 块选择；
- INT8 数据、scale 和索引输出；
- Delta ring 和帧协议；
- FULL + Delta 恢复。

### 3.3 技术路线调整说明

本节用于解释开题方案与当前实现之间的变化，建议控制在 2–3 段。

建议表述：

> 开题阶段以 GPU/BaM 直通存储和多路径写入作为预期技术路线。进入实现阶段后，
> 结合实际 Ascend 910B 实验平台、MindSpore 训练框架和 SPDK 用户态 NVMe 环境，
> 研究对象调整为 NPU 检查点系统。课题所解决的核心问题没有变化，仍是加速器训练
> 检查点的数据路径、异步控制和写入数据量优化；变化主要体现在底层接口由
> CUDA/GDS/BaM 调整为 ACL+SPDK，并进一步形成单所有者 Reactor 控制平面和
> NPU 图内压缩方向。

随后用表格给出路线映射：

| 开题预期 | 当前实现 | 延续的研究问题 |
|---|---|---|
| GPU/BaM 直通 SSD | Ascend ACL + SPDK | 缩短加速器检查点数据路径 |
| GPU 线程轮询优化 | CPU 单所有者 Reactor/FSM | 降低轮询、锁和控制开销 |
| 多路径/SSD 缓冲优化 | FULL 槽、双元数据槽、Delta ring | 提升持久化效率和可恢复性 |

### 5.4 NPU 增量压缩的方案验证

汇报已经完成的验证：

- GRAPH_MODE 中图内 Delta+Top-K+INT8 原型可编译；
- 一次 GPT-2 XL 实验包含 3038 个块，Top-10% 选择 303 个块；
- 量化结果平均绝对差约 0.0002，最大差为一个 INT8 bin；
- quant、scale、index、P_old 缓冲曾获得有效 HBM 地址；
- 阶段 Delta 数据量约 159.4 MB，约为 FULL 的 5.1%，理论缩减约 19.5 倍；
- 159.4 MB 写入耗时约 45 ms，约 3.35 GB/s；
- 单步恢复 NRMSE 中位数约 0.00279，最大约 0.00306。

同时报告负面发现：

- 早期 100 步固定 Top-10% 实验的最终 NRMSE 中位数约 0.76；
- 固定比例会遗漏持续小幅变化的块，误差随恢复链增长；
- 该结果说明需要自适应选择、周期性 FULL 或误差反馈，而不是证明方案已经完成。

不要在本节引用：

- 约 56 GB/s 的错误 pipeline 带宽；
- 输出缓冲为零时得到的 46.6% overhead；
- 将 100 步 NRMSE 曲线表述为恢复成功。
