# 昇腾训推 I/O 控制与 AIV AIC 协同实验路线

规划日期为 2026 年 11 月 10 日。第一阶段从 Qwen3-8B TP4 的 FULL checkpoint 开始。推理 I/O 是第二个验证场景，NeutronSparse 式协同保留为小规模验证线。以下实验、阈值和交付均为计划。

## 1 研究问题与现有证据

先回答一个可以被证伪的问题：**在不改变训练状态、持久化语义和内存预算的前提下，checkpoint 关键路径上有多少等待可以通过调整提交粒度、等待边界或分块流水消除？** 只有在真实路径中找到输入已就绪、可独立执行的 AIV 和 AIC 工作，才进入两类引擎的协同实验。

| 已有证据 | 对本轮路线的含义 |
| --- | --- |
| Qwen3-8B TP4 的 ABI3 FULL 已通过 NPU4–7 定向保存、恢复和发布中断对账。保存仍同步阻塞训练，使用 ACL D2H、Host socket bridge 和单 SPDK owner。 | 有正确性基线可复用。首轮以实际冻结环境复现，补完整性能归因。 |
| 无 checkpoint 的 O1 训练在卡 4 每步约有 149.5–163.4 ms 处于低 AIC、高 AIV 状态。真实模型诊断定位到全局梯度裁剪后的优化器状态搬移与更新，独立 AIC 工作的运行时就绪仍未知。 | 无保存的优化器诊断用作背景对照。记录 checkpoint 特有的等待和计算，保留全局裁剪及优化器依赖。 |
| 推理中已定位特定布局下 FIA 的整池 Slice。连续 K/V 可消除大 Slice。上游已对符合 PA 资格的层采用连续分配，非 PA 路径仍需按版本和后端做回归。 | 先固定可用的推理布局和图模式。用真实 KV 加载或 offload 验证 I/O 假设，将整池 Slice 作为布局回归。 |
| 独立矩阵与向量复制的合成共跑较串行快约 3.6%–4.0%，同时观察到共跑 kernel 变长。真实模型未进入共跑验收。 | 复用合成探针校准观测。重叠时长、引擎忙碌度和端到端收益分别报告。 |

证据来自 [FULL 流程及验收][full]、[训练尾段][train]、[推理 KV 容量][kv]、[推理图与后端][coord]、[上游连续分配修复][pa] 和 [非 PA 路径公开复现][upstream-issue]。

## 2 冻结环境与定义事件

- **训练入口**沿用 FULL 验收归档中的实际 `train.py` 配置和 ABI3 环境。以 Qwen3-8B TP4、固定输入与初始状态开始，记录软件树、实际导入源、二进制哈希、模型与容器身份、驱动和 CANN、物理卡映射、绑核、存储区域和后台负载。FULL 实现及其硬件验收来自独立源码快照，执行时按归档核对。
- **采集点**覆盖每 rank 的训练步结束、快照数据可读、分块提交、D2H 完成、Host bridge 入队和出队、owner 接收与校验、NVMe 提交和完成、payload flush、metadata/anchor 提交、raw receipt、目录发布和各 rank 恢复计算。若数据实际经过 AIV pack/unpack，另记录其任务提交、开始和完成。使用已有指标和事件接口补点，优先避免逐 tensor 打印和人为全设备同步。
- **关联键**至少包括 run、rank、物理设备、训练 step、checkpoint 代、raw request ID、chunk、源缓冲及 slot 代。每条记录包含事件名、时钟域、时间戳、字节数和状态。Host、Device、SPDK 的跨域时延只在有时间锚点或关联事件时计算。性能、短 trace 与 PMU 采集可独立重复，按配置汇总。
- **语义边界**明确记录 `data_ready`、`source_safe`、`durable` 和 `published`。原训练张量、传输源和 Host slot 分别按自己的消费者和完成事件判断可复用时间。单个 chunk 的 ACK 不授予下一训练步提前更新全量训练状态的权限。超时、rank 退出和 close/drain 各自保留完成或失败证据。

阶段退出条件为现有 FULL 保存和 fresh-process 恢复冒烟通过，各 rank 的主要路径可按 ID 关联，并能解释采集覆盖和观测扰动。若关联或时钟校准失败，先补测量，性能结论保持待定。

## 3 训练基线与归因

### 首轮对照

| ID | 配置 | 要回答的问题 |
| --- | --- | --- |
| T0 | 无保存。相同训练负载和采样步号。 | 自然步时、四卡差异与无 I/O 的引擎活动。 |
| T1 | 相同保存边界、tensor 范围、字节数、顺序及 chunk 几何。复用 D2H 源准备与拷贝链，将数据送到有界 Host sink。等拷贝及 sink 消费完成后再复用对应 slot。 | 源准备、D2H 与 staging 的成本。诊断结果记录 sink 行为和字节校验。 |
| T2 | 当前阻塞 FULL，保留四 rank、单 owner、校验、flush 和发布语义。 | 完整保存停顿及慢 rank 的关键路径。 |

先用小样本确认 T1 与 T2 的实际拷贝字节、chunk 几何和源准备一致。若 sink 改变了回压、拷贝批次或拷贝与消费的重叠，记录差异。T1 与 T2 的时延差只作为新增路径的筛查线索，再用 T2 的事件图验证，不能直接报成 NVMe 耗时。

固定保存间隔、训练序列长度、micro-batch、软件栈与 HBM/Host 预算。按预先登记的顺序轮转三组，每组至少三次独立进程启动，报告所有重复及原始样本数。先做短归因，随后增加稳态保存事件；正式报告 P95 前，计划每组至少 30 个稳态保存或对齐的基线窗口，按进程分组保留分布，避免把四 rank 或同一进程内多次保存当成独立重复。预热、编译、恢复、采集收尾和故障重试单列。

### 核心度量

- **训练影响**记录无 profiler 的保存步停顿、常规步时、全程 tokens/s，以及在途工作最终排空耗时。用 T0 对齐步号描述保存额外开销，保留四 rank 的最慢路径。
- **控制路径**拆分 Host 等待、提交、socket 传输和 owner 处理，记录队列高水位、满队列等待、唤醒次数及每次提交的描述符数。用提交、执行和完成事件区分等待与实际服务时间。
- **设备及存储**区分 AIV、AIC、AICPU、DMA 和 NVMe 路径。记录实际读写字节、HBM 流量、Host/HBM 峰值、提交到完成时延、flush 和目录发布开销。对重叠区间取并集或重建依赖关键路径。混合、未知与缺样单独报告。
- **正确性**T2 及后续候选通过 fresh-process 恢复并与无保存 oracle 比较模型、Adam 状态、训练位置/RNG 与后续 loss。重用已登记的哈希、几何和 loss 容差。若候选改变发布或所有权路径，重跑发布中断、慢 rank、队列满、迟到完成和 close/drain 的相关验收。

用独立无采集运行估计探针开销。复用已有测量合同的 10% 扰动上限作为首轮质量门槛；超限 trace 只用于任务和依赖归因。PMU 依各引擎容量归一化，按原生采样粒度报告，避免将 10 ms bin 内的共同活动当成瞬时并行。参见 [原生采样口径][contract]。

## 4 按关键路径选择一个改动

| 归因结果 | 首个可逆干预 | 主要验收 |
| --- | --- | --- |
| Host 提交、复制组织或通知占主导 | 固定数据与协议，合并相邻描述符或批量提交。每次只改一项。 | 提交次数下降，保存停顿和总吞吐改善，队列深度和内存占用受控。 |
| rank 等待或发布等待占主导 | 先区分业务所需的提交、发布屏障和实现造成的提前等待。只缩小有证据支持的等待范围。 | 保存/恢复的可见代、错误传播和慢 rank 行为符合原契约。 |
| AIV 打包在关键路径上 | 固定输入和输出字节，比较逐片段、合并打包与分块流水。先测串行版。 | 输出字节一致，打包与 D2H 分别归因，HBM 压力和保存停顿可复测。 |
| DMA 或介质服务时间占主导 | 扫描少量 chunk 大小或有界队列深度；固定其他变量及 flush 语义。 | 在相同字节与持久化强度下比较关键路径、峰值占用和积压。 |

在看到候选结果前登记实用改善阈值和稳态吞吐非劣界限。首轮可用保存步 P95 额外停顿下降至少 10%、稳态吞吐下降不超过 2% 作为筛选目标，再按基线噪声和目标负载确认阈值后冻结。按独立进程配对报告效果和离散度。每种候选跑过多个保存周期并排空工作，未提交代、未释放 slot 和失败重试如实计入。若主要时间落在不可移动的持久化或数据依赖上，优先交付该边界及可验证的减等待空间。

## 5 NeutronSparse 式协同验证

NeutronSparse 在 SpMM 中按稀疏度把可执行子工作分配给 AIV/AIC，再按进度做流水和剩余工作迁移。这里借鉴其可切分工作、成本平衡和串行对照方法。先从训练 I/O 归因里找一个候选，例如独立冻结分块的 AIV pack 与无需该分块的 AIC 计算。同步训练中的下一步前向只有在所读参数版本正确、依赖完成且相关缓冲生命周期允许时才可作为候选。[NeutronSparse 第 5 节][neutron]

1. **证明就绪。** 给出候选分块的生产完成、消费者依赖、通信、参数版本、alias 和缓冲生命周期。标注 `ready`、`blocked` 或 `unknown` 及对应事件证据。只对两侧可执行的同一段时间做共跑。
2. **验证固定划分。** 分别测 AIC 单独、AIV 单独、相同工作的串行、固定分块共跑。保留数据几何、字节数、算法、输出与生命周期。至少两档分块粒度，检查引擎交集、端到端耗时、各自 kernel 延长、HBM 流量与等待。
3. **按结果决定是否扩展。** 两侧就绪、输出等价、重复中关键路径确实缩短且无持续积压，才考虑动态分块或跨窗口调节。如果候选在合法依赖下无法重叠，或可重叠但带宽竞争和控制开销抵消收益，则记录限制并停在固定划分。若主线暂未出现合法候选，用独立 SpMM 或分块搬运探针作正对照，结果单独归档。

## 6 推理侧验证

训练侧事件口径稳定后，选择一个受支持的 **KV prefix 加载或 offload** 场景。优先复用 vLLM-Ascend connector 和可运行的真实模型；在实际运行前核对模型、硬件、图模式和 P/D 部署支持。避免将 SFA/MLA 稀疏 offload 的支持范围直接用于 Qwen3 普通 GQA。若 910B3 上没有可用且可测的路径，记录具体兼容限制，先保留训练主线结果。[vLLM-Ascend KV offload 设计][offload] · [KV Cache Pool 配置][pool]

- **对照**固定实际 KV 布局、后端、容量、并发和请求轨迹。以同一 connector 的现有等待/加载路径为基线，记录固定命中与 miss，优先对照按需加载和有界预取。常驻 KV 或冷 miss 重算可单独作为参考。
- **事件与指标**记录请求到达、KV 索引命中、加载发起/完成、首个消费、缓存 slot 复用和释放。对比 TTFT、P95 TPOT、吞吐、实际 H2D/D2H 字节、内存与队列高水位。按同一请求定义保存输出及首个分叉 token 的证据，覆盖 b1、多提示词并发与长度变化。
- **门槛**若正式基线依旧触发整池 Slice，先用连续 K/V 或适用的 PA 配置分离布局开销。若图启动、稳定性或输出门槛失败，结果只作兼容性诊断。预取必须保持缓存版本与 slot 所有权正确，并能在相同请求负载下改善端到端指标。

## 7 交付顺序与停止条件

| 阶段 | 最小交付 | 何时继续 |
| --- | --- | --- |
| M0 冻结与冒烟 | 基线身份、资源与区域记录、事件字典、FULL 保存/恢复证据 | 四 rank 运行成功，关键事件可关联，安全边界明确。 |
| M1 训练归因 | T0/T1/T2 的逐进程指标、四 rank 时间线、等待与服务时间拆解 | 能定位首要可改动的瓶颈，或明确主要开销来自必要依赖。 |
| M2 单点优化 | 一项干预的同口径 A/B、内存/积压测量及恢复验收 | 只有收益和正确性同时通过才扩大矩阵。 |
| M3 协同验证 | 一个就绪候选的证据、串行/共跑对照及结果 | 通过端到端门槛再做动态调度；无合法候选时保留独立正对照。 |
| M4 推理验证 | 受支持的 KV I/O 基线、同轨迹 A/B、稳定性及输出报告 | 只在兼容与正确性通过后扩到多并发或更多请求分布。 |

每次实验保留运行命令、配置、源码与环境身份、校验清单、逐 rank/进程统计、时间线、未通过项及失败日志。正式结果区分测量完成、正确性通过、性能通过和未进入验收。硬件执行前复核卡占用、现有 lease 和获准的存储区域。第一项工作是完成 M0，并为 T0/T1/T2 登记实验参数与采集点。
