# 1 课题的来源、目的及意义

## 1.1 课题来源

本课题来源于国家自然科学基金青年基金项目“运行时信息耦合驱动的大规模图神经网络异构资源高效协同机制研究”（No. 62402187），以及华中科技大学鲲鹏昇腾科技创新孵化中心创新课题“面向 AI 应用的异构存算资源层次化存储融合关键技术研究”。课题面向大规模人工智能训练中的高效存储与可靠性保障需求，研究对象由开题阶段预期的 GPU 直通存储方案进一步聚焦为 Ascend NPU 训练环境下的高频检查点系统，核心问题仍然是如何缩短加速器训练状态到持久化存储的数据路径、降低检查点对训练过程的干扰，并减少频繁保存所需写入的数据量。

## 1.2 研究背景

近年来，深度神经网络特别是大语言模型的参数规模、训练数据规模和集群规模持续增长。大模型训练通常需要综合采用数据并行、张量并行、流水并行以及优化器状态分片等技术，将模型参数、梯度和优化器状态分散到大量计算节点和加速器上。与单机训练相比，这类训练任务不仅执行周期更长，而且包含更多 GPU/NPU、网络设备、存储设备和软件组件，任一环节出现故障都可能导致整体训练中断。Meta 公布的 Llama 3 405B 训练记录显示，在一个连续 54 天的预训练阶段内，系统发生了 419 次非预期中断，平均约每 3 小时出现一次[1]。这说明随着训练规模扩大，故障已经不是低概率的例外事件，而是大规模训练系统必须持续面对的常态问题。

检查点是保障长周期训练可靠性的基本机制。系统按照一定周期保存模型参数、优化器状态、学习率调度状态、随机数状态以及数据加载进度等信息；故障发生后，训练任务可以从最近一次完整且一致的检查点恢复，而无须从头开始执行。检查点间隔越短，故障后需要重复执行的训练步数越少，但保存操作对正常训练造成的开销越高；检查点间隔越长，稳态训练开销较低，但发生故障后会损失更多已经完成的计算。因此，高频检查点的核心目标并不是简单增加保存次数，而是在检查点一致性、持久性和可恢复性得到保证的前提下，降低单次保存成本，使系统能够采用更短的保存周期。

传统深度学习框架通常采用“加速器内存—主机内存—文件系统—持久化存储”的检查点路径。触发保存后，训练框架首先遍历模型及优化器状态，将分散的张量转换为可序列化对象；随后将加速器内存中的数据复制到主机内存，在 CPU 侧完成格式组织和序列化，最后调用文件系统接口写入本地或远端存储。这种方法实现简单、通用性较强，但存在三方面问题。第一，快照、序列化和文件系统写入组成了较长的软件路径，随着模型状态增大，训练线程可能产生显著停顿。第二，异步检查点虽然能够将持久化放到后台执行，但通常仍需要在 GPU/NPU 内存或主机 DRAM 中保留一份快照，带来额外内存占用；当训练本身已经通过参数或优化器卸载消耗大量主机内存时，检查点快照可能进一步加剧内存压力。第三，全量检查点每次都保存完整模型状态，即使相邻训练步之间只有部分参数块发生了较显著的变化，也仍然需要传输和写入全部数据，容易形成持续的 PCIe 和 NVMe 带宽压力。

高速 NVMe SSD 的发展使底层存储设备能够提供较高顺序吞吐和大量并发队列，但通用内核 I/O 栈、文件系统语义以及频繁的上下文切换可能使应用难以充分利用设备能力。SPDK 将 NVMe 驱动和 I/O 处理移到用户态，采用异步 queue pair、轮询和 DMA 缓冲区等机制，能够绕过传统文件系统和内核块层的部分开销[2]。SPDK 同时强调 queue pair 的线程所有权：一个 I/O queue pair 通常由固定线程独占，其他线程应通过消息传递将请求交给其所有者处理[3]。这一模型适合构建高吞吐、低锁竞争的数据通路，但也意味着上层检查点系统必须重新组织并发控制、请求队列、完成通知和异常处理，不能简单地让训练线程或多个 Python 后台线程直接操作同一 I/O 队列。

在加速器侧，GPUDirect Storage、BaM 等研究已经证明，缩短 GPU 与存储之间的数据路径、减少 CPU 中转和控制开销能够显著提升数据密集型负载的 I/O 效率[4][5]。但是，这些方案主要面向 NVIDIA GPU 生态，其硬件直通条件、编程接口和存储访问模型不能直接迁移到 Ascend NPU。结合本课题的实际实验平台，当前系统采用 Ascend ACL 完成 NPU HBM 与主机侧 SPDK DMA 缓冲区之间的数据搬运，再由 SPDK 直接向裸 NVMe 设备提交读写命令。该路线并非硬件 PCIe P2P，也不是严格意义上的完全零拷贝，而是一条绕过通用文件系统、面向检查点大块顺序 I/O 的用户态分块流水化通路。如何在这一通路上组织可靠的裸盘布局、检查点元数据、异步读写和训练步触发，构成了本课题的第一个核心问题。

此外，单纯缩短数据通路仍不足以实现低干扰的高频检查点。一方面，SPDK 的高性能依赖固定线程轮询和 queue pair 单所有者约束；另一方面，检查点又需要由 Python 训练逻辑、NPU 训练步状态和持久化完成事件共同驱动。如果采用多个后台线程直接执行 I/O，容易形成锁竞争、qpair 越权访问、资源回收顺序不确定等问题；如果使用全程同步方式，又会重新引入训练阻塞。因此，需要构建事件驱动的控制平面，由单一 Reactor 线程拥有 SPDK I/O 资源，通过请求环、有限状态机和完成标志推进读写过程，使训练线程只负责提交命令而不参与底层 I/O 轮询。这构成了本课题的第二个核心问题。

最后，即使用户态数据通路和异步控制平面能够充分利用 NVMe 带宽，频繁全量保存仍会消耗与模型状态规模成正比的数据传输和存储资源。已有研究表明，差分检查点、稀疏更新检测和量化可以显著减少检查点数据量[6][7]，但现有方法或者依赖推荐模型嵌入表的稀疏更新特征，或者在 CPU 侧执行压缩，仍可能产生大规模的 NPU—CPU 数据传输。Ascend NPU 训练中部分 Vector 计算资源存在可利用空间，因此，本课题进一步探索在 NPU 训练图内完成块级参数变化检测、Top-K 块选择和 INT8 量化，使压缩后的检查点数据在离开 HBM 前已经完成筛选和编码，并通过周期性全量检查点与增量检查点链实现恢复。这构成了本课题的第三个核心问题。

## 1.3 研究目的

本课题旨在设计并实现一套面向 Ascend NPU 大模型训练的高频检查点原型系统，在保证检查点一致性、完整性、持久性和可恢复性的基础上，从数据通路、控制平面和数据缩减三个层面降低检查点开销。课题并不以复现某一种 GPU 直通存储技术为目标，而是结合 Ascend NPU、MindSpore 训练框架和本地 NVMe 设备的实际软硬件条件，形成可运行、可验证并能够继续扩展的 NPU—NVMe 检查点系统。

第一，构建基于 ACL 与 SPDK 的文件系统旁路检查点读写通路。系统需要支持 NPU HBM 和 Host 内存中的大规模张量，按照满足 NVMe DMA 与裸盘访问要求的对齐方式进行分块，通过有界 DMA 缓冲区池和异步 SPDK 命令完成 HBM—DMA buffer—NVMe 的流水化传输。同时，需要设计超级块、双元数据槽、全量检查点槽位以及参数到裸盘偏移的映射，使直接写入裸设备的数据仍然具备明确的版本、边界和恢复语义。

第二，构建基于单所有者 Reactor 的异步检查点控制平面。由固定 Reactor 线程统一拥有 SPDK queue pair，并在该线程内推进读、写和元数据请求；Python 训练线程通过环形请求队列提交操作，不直接接触底层 I/O 资源。系统使用有限状态机将一次长时间检查点拆分为 DMA、NVMe 提交、完成回收和元数据提交等有界阶段，并通过 NPU step counter 和持久化完成标志实现训练步级的 Fire-and-Forget 触发。该设计的目标是在不破坏 SPDK 线程模型的前提下减少锁竞争和 CPU 忙等待，并使检查点完成状态能够被训练程序可靠观测。

第三，探索 NPU 图内块级增量检查点生成与压缩方法。系统对连续版本的参数进行分块，在训练图中计算参数差值及块级变化度，选择变化较显著的 Top-K 数据块，并将其量化为 INT8 数据，同时保存恢复所需的缩放因子、块索引和版本信息。持久化层采用周期性 FULL 检查点作为恢复基线，在相邻 FULL 之间保存 Delta 帧，故障后先加载最近一次完整检查点，再按顺序应用增量数据。该方向重点研究压缩率、图内计算开销、量化误差、Delta 链长度和恢复精度之间的权衡，而不是将固定 Top-K 比例或单步量化结果直接视为最终方案。

通过上述研究，课题希望形成“图内少写—后台稳控—用户态快传”的完整技术链：NPU 图内计算减少需要传输的数据量，Reactor 控制平面负责安全异步调度，SPDK 数据通路完成高带宽持久化。三个部分分别对应数据生成、I/O 控制和存储执行层，又通过统一的检查点格式和恢复语义形成整体。

## 1.4 研究意义

在理论与方法层面，本课题有助于拓展面向异构加速器的检查点系统研究。现有高频检查点工作主要关注如何将快照和持久化与 GPU 计算重叠，GPU 直通存储研究主要关注如何减少 CPU 参与，而检查点压缩研究主要关注如何降低存储容量或传输数据量。三类研究往往分别优化某一层次。本课题将 NPU 图内增量数据生成、SPDK 单所有者控制和用户态裸盘持久化置于同一系统中考察，可以分析计算、数据搬运、控制轮询与存储写入之间的耦合关系，为后续研究检查点频率、资源利用率和恢复误差的联合优化提供基础。

在系统设计层面，本课题能够形成一套适配 Ascend NPU 的检查点路径与控制机制。与直接套用 GPU 生态中的 GDS 或 BaM 不同，课题尊重现有平台能力边界，通过 ACL 与 SPDK 组合缩短通用软件路径，并围绕 SPDK queue pair 所有权构建 Reactor、请求环和状态机。这种设计既避免将现有实现夸大为硬件 P2P，也能够实质性减少文件系统参与、同步等待和多线程锁竞争，为 NPU 训练任务使用本地高速 NVMe 提供可验证的工程方案。

在应用层面，降低检查点保存开销能够支持更高的保存频率，从而减少故障后的训练回退量和重复计算量。对于长周期、大规模训练任务，检查点性能的改进不仅关系到单次 I/O 延迟，也会影响加速器有效利用率、训练完成时间、存储带宽占用和故障恢复目标。若能够在不显著影响训练吞吐的情况下缩短检查点周期，就有望减少因硬件故障、软件异常或任务抢占造成的算力浪费，提升训练平台的可靠性和资源经济性。

在国产软硬件生态层面，Ascend NPU 与鲲鹏处理器是重要的人工智能计算平台，但围绕 NPU 训练检查点与本地 NVMe 协同优化的公开系统研究相对有限。本课题基于 MindSpore、CANN/ACL、SPDK 和 NVMe 构建端到端原型，可以沉淀 NPU 张量地址管理、DMA 缓冲区组织、ARM64 并发内存语义、裸盘元数据和异步恢复等方面的实践经验，为国产加速器训练系统的软件栈优化提供参考。

在后续扩展层面，本课题形成的数据通路与控制平面不仅可以服务模型参数检查点，还可以扩展到优化器状态卸载、训练中间结果持久化、模型版本管理以及其他大块加速器数据写入场景。NPU 图内增量生成方法也为利用加速器空闲计算资源执行数据筛选、编码和压缩提供了新的研究视角。因此，本课题兼具检查点领域的直接应用价值和异构存算协同领域的方法参考价值。

# 2 国内外研究概况

## 2.1 深度学习训练与检查点存储过程

深度学习训练通常以迭代为基本执行单位，每次迭代依次经历数据读取、前向传播、损失计算、反向传播和参数更新。前向传播根据当前模型参数计算预测结果，并保存反向传播所需的中间激活；反向传播依据损失函数和链式法则计算参数梯度；优化器随后结合梯度、学习率以及动量或二阶矩估计更新模型参数。对于 Adam 等优化器，除模型参数外，训练过程还维护与参数规模相当甚至更大的优化器状态。因此，可恢复的训练检查点通常不仅包含模型权重，还需要包含优化器状态、学习率调度器状态、混合精度缩放状态、随机数生成器状态、训练步数以及数据加载进度等信息。

从保存时序看，检查点可以分为同步检查点和异步检查点。同步检查点在训练步边界暂停计算，完成状态收集、序列化和持久化后再继续训练，易于保证一致性，但会直接形成训练停顿。异步检查点通常将操作划分为“快照”和“持久化”两个阶段：训练线程先获得某一逻辑时刻的一致状态副本，再由后台任务将副本写入持久化介质。该方法能够隐藏部分存储时间，却需要额外缓冲空间，并要求快照在下一次参数更新前完成，否则可能把不同训练步的状态混合到同一检查点中。

从数据范围看，检查点又可以分为全量、差分和增量形式。全量检查点独立保存恢复所需的全部状态，恢复过程简单、链路短，但每次写入量大。差分或增量检查点只保存相对于某个基线版本发生变化的数据，能够降低写带宽和存储容量，但恢复时需要加载基线并重放一个或多个增量版本；如果增量数据经过有损稀疏化或量化，还必须控制误差随恢复链增长而累积。由此可见，高频检查点并不是单一的 I/O 优化问题，而是训练一致性、快照内存、数据路径、持久化协议和恢复精度共同约束下的系统问题。

## 2.2 异步与高频检查点研究

传统深度学习框架中的串行检查点通常按照固定 epoch 或训练步间隔触发。训练进程在保存期间停止参数更新，将模型及优化器状态转换为框架支持的序列化格式，并通过文件系统写入本地盘或共享存储。该方案通用性较好，但检查点时间会随模型规模增长。当保存时间明显长于单次迭代时间时，频繁触发会导致加速器长时间空闲；若为降低开销而扩大检查点间隔，又会增加故障后的重复计算量。因此，国内外研究首先围绕如何重叠快照、I/O 和训练计算展开。

Mohan 等提出 CheckFreq，以迭代级检查点替代传统 epoch 级保存[8]。CheckFreq 将检查点拆分为快照和持久化两个阶段：在保证参数一致性的时间窗口内复制模型状态，并将后续写入与下一轮训练计算进行流水化；同时通过在线分析选择初始保存频率，并根据运行时干扰动态调节频率。该工作还关注数据加载器的可恢复性，避免恢复后重复或遗漏训练样本。实验表明，CheckFreq 能够将故障后的训练回退从小时级降低到秒级，并将运行开销控制在 3.5% 以内。CheckFreq 建立了“训练语义感知快照 + 后台持久化 + 动态频率”的经典高频检查点范式。

DeepFreeze 面向并行深度学习训练，将序列化和 I/O 负载分散到参与训练的进程，并使用异步多级检查点隐藏持久化开销[9]。DataStates-LLM 进一步针对大语言模型检查点中张量数量多、分片异构和主机缓冲分配开销大的问题，利用模型参数和优化器状态在前向、反向阶段保持不变的时间窗口执行惰性非阻塞快照，预先分配并复用锁页主机缓冲区，同时对碎片化张量进行合并和流式持久化[10]。这类研究说明，理解训练状态在一次迭代内的可变与不可变阶段，是降低快照阻塞和实现安全重叠的重要基础。

FastPersist 从底层 NVMe 利用率出发，通过优化 SSD 写入、利用多个数据并行 rank 的本地 SSD 并行持久化，并将检查点写入与后续独立训练计算重叠，在其测试环境中实现了显著的检查点加速[11]。PCcheck 则指出，部分异步方案仍需等待上一份检查点完全持久化后才能启动下一份检查点，限制了高频保存能力。PCcheck 允许多份检查点同时处于复制和持久化阶段，通过分块、GPU—CPU 与 CPU—存储两级流水线以及多个持久化线程提高并发度，在 SSD 和持久内存场景中支持单机及分布式训练[12]。其结果表明，在适当控制并发检查点数量和资源占用后，可以以较低训练吞吐开销实现更高保存频率。

除了周期性异步保存，Just-In-Time Checkpointing 从故障触发时机出发提出另一种恢复思路：不在稳态训练中频繁生成完整持久化检查点，而是在检测到故障后利用仍存活的训练状态构造可恢复快照，使恢复时仅需重放少量工作[13]。该方法减少了周期性检查点的稳态开销，但依赖故障检测、剩余设备状态可用性和特定训练运行时支持，与本课题面向本地 NVMe 的周期性持久化目标不同，适合作为替代范式进行比较。

国内研究在细粒度异步检查点和软硬件协同方面也取得了较有代表性的成果。华中科技大学提出 LightCheck，利用分布式训练中的层级数据依赖和通信间隙执行细粒度异步检查点，并通过持久内存管理器组织 GPU 到 PM 的数据传输[14]。LightCheck 提供 GPU 内复制、CPU 内复制以及 GPU 到 PM 分层传输等策略，在检查点频率、额外显存/内存占用和持久化性能之间进行权衡。CheckFlow 将需要保存的参数快照视为具有创建、驻留和卸载生命周期的张量，把相关操作连同显存约束、执行顺序和数据传输约束共同建模为整数线性规划问题，从计算图层面对检查点与训练操作进行统一调度[15]。与固定流水线相比，该方法更强调在显存可行的前提下寻找低峰值占用的调度方案。

总体来看，异步与高频检查点研究已经形成快照—持久化分离、分块流水化、训练语义感知和多版本并发等主要技术路线。然而，大部分方案仍依赖主机内存快照、CPU 序列化和文件系统持久化；多个复制和 I/O 线程还可能引入锁竞争与资源管理复杂度。现有工作主要回答“何时快照、如何与训练重叠”，对于用户态 NVMe queue pair 的所有权、跨语言请求提交以及 NPU 运行时触发等控制问题涉及较少，这为本课题的 Reactor 控制平面留下了研究空间。

## 2.3 分布式检查点格式、存储与恢复研究

大模型通常采用混合并行策略，将模型参数、梯度和优化器状态切分到多个 rank。传统集中式检查点需要先聚合分片再保存，容易形成单点内存和 I/O 瓶颈；分布式检查点允许各 rank 并行写入自己的状态分片，但保存结果往往与当时的并行策略、rank 数量和硬件配置绑定。当恢复所使用的设备数量或并行维度发生变化时，系统还需要对检查点进行重分片。因此，分布式检查点研究除关注保存带宽外，还关注检查点表示、分片元数据、跨配置加载和故障恢复位置。

Gemini 针对远端持久化存储恢复速度较慢的问题，使用本地 CPU 内存、远端节点 CPU 内存和远端持久化存储构成分层检查点体系[16]。其核心是通过检查点放置策略提高故障发生后仍能从集群内存恢复的概率，并调度检查点通信，降低其与训练集合通信的干扰。软件故障可以优先从本机或集群内存恢复；当部分节点故障时，从存活节点获得检查点分片；只有更极端情况下才回退到远端持久化存储。Gemini 表明，分层介质选择和故障类型感知能够显著缩短恢复时间，但内存检查点仍需要与持久化检查点配合，才能应对节点级或集群级故障。

ByteCheckpoint 由字节跳动与香港大学合作提出，面向大模型从预训练、后训练到评测和模型转换的完整生命周期[17]。该系统采用与并行策略无关的检查点表示，在加载阶段根据目标并行配置执行重分片，并使用通用保存/加载流程适配不同训练框架和存储后端。ByteCheckpoint 还从计划生成、张量处理、通信、存储后端和监控工具等方面进行全栈优化。其工业级实践说明，检查点不仅用于故障恢复，也承担模型阶段转换、资源弹性和评测分发等功能，因此格式通用性和可观测性与单次写入性能同样重要。

Universal Checkpointing 同样针对分布式检查点与训练并行配置紧耦合的问题，设计统一检查点格式及模式驱动的转换流程，使模型能够从一种数据、张量、流水或专家并行配置转换到另一种配置恢复[18]。其核心思想是在保存阶段保留分布式写入效率，在转换和加载阶段形成与目标并行配置匹配的表示。该方向的重点是逻辑状态组织与重配置能力，与单节点底层存储路径优化属于不同层次。

国内团队还开展了异构路径和新型存储介质上的分布式检查点研究。华中科技大学与中国移动提出 ParaCkpt，面向 GPU—NVMe、CPU—NVMe 等异构数据路径构建多路径检查点机制[19]；上海科技大学提出 Portus，利用 GPU 到持久内存的 RDMA 数据路径和三级索引，减少主机内存中转、序列化以及文件系统访问，并通过异步机制隐藏持久化开销[20]。这些工作说明，分布式检查点正在从单一共享文件系统写入发展为结合本地 SSD、持久内存和直接数据传输的多层架构。

上述研究主要解决跨 rank 状态组织、并行无关表示、分层恢复和多路径传输问题。本课题当前不以重新定义分布式检查点格式为主要目标，而是面向单节点 Ascend NPU 和本地 NVMe 构建下层持久化后端。未来可将本课题的数据通路接入上层分布式框架，使各 rank 以并行无关的元数据组织逻辑状态，并调用本地 SPDK 后端完成高带宽保存。因此，中期报告应将两类研究表述为上下层互补关系。

## 2.4 加速器直通存储与用户态 NVMe 研究

传统加速器访问存储时，数据通常先由存储设备传入主机内存，再经 PCIe 复制到 GPU/NPU 内存；写回过程则按相反方向执行。该路径不仅产生主机内存中转，还包含文件系统、内核块层、系统调用和中断等软件开销。随着 NVMe SSD 和加速器带宽提高，通用 I/O 软件栈的开销在端到端路径中占据更大比例，推动了 GPUDirect Storage、GPU 主导 I/O 和用户态存储栈等方向的发展。

NVIDIA GPUDirect Storage 为 GPU 显存与本地或远端存储之间提供直接 DMA 路径，避免通过 CPU 内存 bounce buffer，并通过 cuFile 接口向应用提供文件或块存储访问能力[4]。GDS 可以降低 CPU 负载和多余内存拷贝，但其 I/O 请求主要由 CPU 侧 API 发起，对细粒度、运行时数据相关的存储访问仍需要主机参与控制。与此同时，GDS 的可用性受到 GPU、驱动、文件系统、PCIe 拓扑和存储设备支持等条件约束。

Qureshi 等提出 BaM，通过将 NVMe 队列和门铃寄存器映射到 GPU 可访问空间，使 GPU 线程能够自主发起细粒度存储请求[5]。BaM 使用高并发队列隐藏 SSD 访问延迟，并设计 GPU 侧软件缓存以合并请求、减少 I/O 放大。其研究主要针对图分析、推荐和数据分析等不规则访问负载，证明 GPU 主导存储访问能够减少 CPU 编排和同步开销。但 BaM 需要大量 GPU 并发线程维持在途请求，I/O 提交、完成轮询、缓存访问和计算之间可能发生 GPU 核心竞争。

GPM 面向 GPU 无法直接利用持久内存的问题，利用统一虚拟地址将 PM 映射到 GPU 地址空间，并结合系统级内存栅栏和平台持久化控制，使 GPU 内核能够执行细粒度 load/store 和持久化操作[21]。Portus 则将直接 GPU—PM 数据路径用于 DNN 检查点。需要注意的是，持久内存具有字节寻址和 load/store 语义，而 NVMe SSD 使用块设备命令与队列语义，两类方案在一致性、地址映射和完成通知方面存在明显差异，不能直接等同。

浙江大学等单位提出 Hyperion，将 GPU 发起的 SSD I/O 提交和完成处理拆分到不同内核，并与 GNN 采样、缓存访问和训练计算形成流水线[22]。该工作表明，对提交与完成阶段进行解耦能够减少 GPU 线程在等待 SSD 响应期间的浪费。Hyperion 的应用对象是超大规模图数据的外存训练，而不是模型状态检查点，但其“区分 I/O 提交和完成、限制 I/O 占用的计算资源、重叠存储与计算”思想对检查点控制路径具有参考价值。

除 GPU 直通路线外，SPDK 通过用户态 NVMe 驱动缩短 CPU 主导的存储软件路径。应用可直接分配 DMA 内存、创建 NVMe queue pair，并以异步方式提交命令和轮询完成队列[2]。SPDK 的 I/O 路径不使用内部数据缓冲区，数据直接在应用提供的 DMA 缓冲区与 NVMe 设备之间传输。为了避免高性能路径中的锁开销，SPDK 推荐每个 queue pair 由单一线程拥有，将其他线程的操作转换为发送给所有者线程的消息[3]。相关研究对 libaio、io_uring 和 SPDK 的比较也表明，轮询策略、核绑定和多设备组织方式会显著影响性能与 CPU 消耗[23]。

国内外现有加速器直通存储研究主要集中在 NVIDIA GPU、持久内存或图数据访问，公开文献中针对 Ascend NPU 训练检查点与 SPDK 裸盘后端的系统工作相对有限。本课题采用 ACL 将 NPU HBM 数据搬运到 SPDK DMA 缓冲区，再通过 SPDK 访问 NVMe。该路径仍存在一次 HBM 与 Host DMA buffer 之间的数据传输，因此不能称为硬件零拷贝；其优势在于绕过通用文件系统，能够针对检查点的大块顺序写特征控制分块、对齐、队列深度和缓冲区复用。相较于 GDS 和 BaM，本课题的研究重点是 NPU 运行时适配、裸盘检查点语义以及 CPU 单所有者 Reactor，而不是 GPU 线程直接驱动 SSD。

## 2.5 增量与压缩检查点研究

异步检查点通过隐藏 I/O 时间降低训练停顿，但不能消除全量保存的数据规模。随着模型参数和优化器状态增大，即使后台写入不会立即阻塞训练，也可能持续占用 PCIe、主机内存和 NVMe 带宽，并与下一次检查点发生重叠。因此，差分、增量、稀疏化和量化逐渐成为检查点系统的重要研究方向。

Chen 等提出 LC-Checkpoint，通过量化、重要信息优先保存和 Huffman 编码构造面向深度学习训练的有损检查点[6]。该方法在考虑压缩率的同时关注恢复速度，通过保留对 SGD 恢复更重要的信息降低有损压缩的影响。其实验报告最高达到 28 倍压缩率和 5.77 倍恢复加速，说明检查点不一定需要逐位保存全部浮点状态，但压缩策略必须与恢复任务及训练算法相结合。

Check-N-Run 面向超大规模深度学习推荐模型，观察到嵌入表在每次迭代中只更新少量条目，因此通过追踪修改部分构造差分检查点，并使用量化进一步降低检查点大小[7]。其在真实推荐模型上的实验显示，所需写带宽降低 6～17 倍，容量需求降低 2.5～8 倍。该方法说明应用语义能够显著提升增量检查点效率，但其收益与嵌入表的稀疏更新紧密相关。对于稠密 Transformer，几乎所有权重在优化器更新后都可能发生数值变化，因此不能直接采用“是否被更新”判断增量范围，而需要基于变化幅度、块重要性或误差预算进行选择。

Inshrinkerator 进一步研究训练阶段、权重类型和压缩精度之间的动态关系，针对不同权重选择从全精度保留、不同位宽量化到剪枝的非均匀压缩配置，并通过面向量化的差分重排减少相邻检查点差异[24]。其评测报告最高 39 倍压缩率，并考察了多次恢复后的模型质量。与固定量化方案相比，该工作强调压缩配置应随训练进程和参数敏感性动态变化，这对本课题后续设计自适应 Top-K 和误差反馈机制具有直接参考价值。

近年来还有研究使用相邻检查点预测和上下文建模进行熵编码，利用连续训练版本之间的数值相关性提高压缩率[25]。这类方法能够进一步降低长期存储容量，但预测、编码和解码过程通常在 CPU 侧执行，若其计算时间超过节省的 I/O 时间，可能无法降低训练关键路径开销。因此，检查点压缩不仅需要比较压缩率，还需要测量压缩生成时间、加速器到主机的数据量、恢复时间以及对训练精度的长期影响。

本课题第三个方向与上述工作既有联系又有区别。其基本思想同样利用相邻版本差异、块级稀疏选择和低精度量化，但将 Delta 计算、块变化度统计、Top-K 选择和 INT8 量化尽量放入 NPU 训练图中完成。这样可以在数据离开 HBM 前缩减需要传给 SPDK 后端的数据，而不是先将完整参数复制到 CPU 再压缩。对于恢复协议，系统计划周期性保存 FULL 检查点，在两个 FULL 之间保存包含块索引、量化值、缩放因子和版本信息的 Delta 帧。恢复时从最近 FULL 开始顺序应用 Delta，以限制单个增量检查点不可独立恢复的问题。

图内增量压缩仍面临若干开放问题。第一，固定 Top-K 比例可能长期忽略幅度较小但持续变化的参数块，造成误差累积。第二，INT8 量化需要保存准确的 scale 和块映射，元数据缺失会使压缩数据无法恢复。第三，Delta 链越长，恢复延迟和累计误差越大，需要确定 FULL 刷新周期。第四，图内压缩占用 NPU Vector 计算和 HBM 缓冲，其收益必须大于增加的训练步开销。第五，模型参数和优化器状态具有不同分布与精度敏感性，可能需要分别设计选择和量化策略。因此，中期阶段应将该方向表述为已完成方案设计和关键可行性验证、正在进行误差控制与端到端协议验证，而不能仅凭单步压缩率宣称完整方案已经实现。

## 2.6 研究现状总结

综合国内外研究，可以将深度学习检查点优化概括为四条主线：一是通过快照—持久化分离、流水化和训练语义感知调度隐藏保存时间；二是通过分布式格式、分层内存和重分片机制提高大模型检查点的扩展性与恢复灵活性；三是通过 GPUDirect Storage、GPU 主导 I/O、持久内存以及 SPDK 用户态驱动缩短加速器与存储之间的数据和控制路径；四是通过差分、稀疏化、量化和熵编码减少需要传输与保存的数据量。

国外研究在 CheckFreq、DataStates-LLM、PCcheck、Gemini、Universal Checkpointing、BaM 和 Inshrinkerator 等工作中形成了从训练调度、分布式恢复到加速器存储访问和动态压缩的完整技术谱系。国内高校和企业则在 LightCheck、CheckFlow、ByteCheckpoint、ParaCkpt、Portus 和 Hyperion 等系统中，对层级异步检查点、工业级大模型状态管理、异构多路径、GPU—持久内存直通和 GPU 发起 SSD 流水线进行了深入探索。

然而，现有方案仍具有明显的层次分离特征。异步方案主要优化检查点与训练的时间重叠，但通常保留主机快照和文件系统路径；分布式方案主要优化逻辑状态组织、跨 rank 保存和重分片，较少涉及单节点 NPU—NVMe 数据通路；加速器直通方案主要面向 NVIDIA GPU 和特定 P2P 硬件条件；增量压缩方案则多针对稀疏推荐模型或在 CPU 侧执行压缩。针对 Ascend NPU，目前仍缺少将图内增量数据生成、用户态 NVMe 持久化、SPDK qpair 单所有者控制以及训练步级后台触发统一起来的检查点系统。

基于上述研究空白，本课题形成“快传、稳控、少写”三层技术路线：利用 ACL 与 SPDK 构建文件系统旁路的 NPU—NVMe 分块流水化数据通路；利用单所有者 Reactor、请求环和读写有限状态机构建符合 SPDK 并发模型的异步控制平面；利用 NPU 图内 Delta、Top-K 和 INT8 量化探索增量检查点生成，并通过 FULL + Delta 协议控制恢复链。该路线不是对 GDS、BaM、CheckFreq 或 Check-N-Run 的简单移植，而是面向 Ascend NPU 训练平台，将已有研究中分别存在的数据通路、异步控制和数据缩减思想组合并落实为端到端检查点系统。
