## 1. 近期目标与交付物

近期工作围绕三个问题展开：

1. **为什么需要面向异构存储层次优化检查点 I/O 路径？** 量化 HBM、Host DRAM、
   内核文件系统和用户态裸 NVMe 之间各层软件栈的时间、搬运与 CPU 开销。
2. **当前设计中的每个技术点分别贡献了什么？** 通过一次只改变一个因素的消融实验，
   区分文件系统旁路、批量提交、分块流水、单所有者 Reactor、FaF 触发等设计收益。
3. **增量检查点应沿哪条路线继续实现？** 先观察参数更新的稀疏性、时间局部性、量化
   误差和长期累积，再从无损基线、自适应选择、量化状态和残差反馈方案中作出选择。

本阶段应形成以下可验收交付物：

- 一套统一的 I/O 路径分层计时与环境采集工具；
- 一组通过数据一致性检查的 FULL 保存、加载和训练干扰结果；
- 一张“软件栈分层开销”图和一张“端到端路径对比”图；
- 一组设计点消融表，能够把收益归因到具体机制；
- 一份增量检查点观察实验数据集和路线选择结论；
- 至少一条能够完成 `FULL + N 个 Delta → 恢复 → 数值校验` 的正确性实现；
- 可复现的命令、配置、原始日志、结果 JSON 和绘图输入，不再依赖手工摘录数字。

## 2. 所有实验的共同前置条件

### 2.1 正确性门禁

性能实验开始前必须完成：

1. 修复 FULL 区域与 Delta ring 的物理地址重叠，形成唯一分区表；
2. 在目标服务器完成 Host/NPU × 读/写四条路径的数据回环测试；
3. 完成 FULL 保存、进程重启、FULL 加载和逐参数校验；
4. 明确 `save()` 的“已派发”和“已持久化”两个完成时刻，后台错误必须使实验失败；
5. 固定目标 NVMe、NPU、NUMA 节点和设备绑定状态，禁止不同物理盘的数据直接横比；
6. Delta 实验必须先通过帧校验、边界检查和恢复校验，失败样本不能进入性能均值。

### 2.2 统一实验协议

每个配置至少预热 5 次，正式重复不少于 10 次；超长训练实验可使用 3 次独立重复，
但必须报告置信区间。所有比较固定：模型、参数精度、数据集、训练步数、检查点间隔、
NVMe 设备、CPU 亲和性、NPU/NUMA 拓扑和后台负载。

每次运行至少保存：

| 类别 | 必须记录的内容 |
|---|---|
| 版本 | Git commit、分支、dirty 状态、子模块 commit |
| 硬件 | CPU/NUMA、NPU、NVMe 型号与固件、PCIe 拓扑、容量与 LBA 大小 |
| 软件 | 内核、CANN、驱动、MindSpore、SPDK、DPDK、Python、编译器版本 |
| 配置 | 路径类型、chunk size、pipeline depth、batch 大小、检查点间隔、模型规模 |
| 性能 | 端到端时间、训练阻塞、各层时间、带宽、CPU 利用率、上下文切换、尾延迟 |
| 正确性 | 写入字节、读取字节、校验和、逐参数误差、恢复后 loss、异常与退出码 |

原始结果写入 `experiments/output/`；进入论文或答辩前，再将通过门禁的结果连同环境
清单固化到带日期和 commit 的结果目录。图表只能从结构化结果自动生成。

## 3. 工作包一：异构存储必要性与 I/O 软件栈开销

### 3.1 需要回答的研究问题

- 通用检查点路径的主要开销来自框架序列化、D2H 快照、文件系统，还是设备写入？
- 绕过文件系统后，节省的是 CPU 时间、数据拷贝、尾延迟，还是端到端带宽？
- HBM、Host DRAM 和 NVMe 的带宽/容量差异如何转化为训练停顿？
- 当模型规模、参数对象数量和检查点频率变化时，直通路径的收益是否仍然成立？
- 写入带宽提高后，新的瓶颈位于 ACL 搬运、任务编组、Reactor 还是元数据提交？

### 3.2 对照路径

| 编号 | 路径 | 目的 | 当前入口或实现基础 |
|---|---|---|---|
| P0 | 纯训练，不保存 | 获得训练 step 基线 | `ProbeTrainOneStepCell(enable_probe=False)` |
| P1 | `ms.save_checkpoint` → 文件系统 → NVMe | 通用框架基线 | `experiments/baselines/ms_save_bench.py` |
| P2 | HBM → Host DRAM 快照 → 内核文件系统 → NVMe | 分离快照与持久化开销 | `checkfreq_kernel_fs.py`、`pccheck_kernel_fs.py` |
| P3 | Host buffer → SPDK → 裸 NVMe | 隔离文件系统和 NPU 搬运 | Host 批量 C API 与 C smoke test |
| P4 | HBM → DMA buffer → SPDK → 裸 NVMe | 当前全量直通路径 | `DirectCheckpoint.save()` |
| P5 | 训练步触发 → 后台 P4 | 测量可隐藏时间与实际训练干扰 | FaF/Reactor 路径 |
| P6 | 裸 NVMe → DMA buffer → HBM/Host | 补齐读取与恢复路径 | `DirectCheckpoint.load()` 与读 API |

P1、P2 与 P4 必须使用同一块 NVMe 或性能等价的独占分区；如果文件系统盘与 SPDK
裸盘不是同一设备，应先分别测得设备上限，并将“设备差异”和“软件路径差异”分开报告。

### 3.3 分层计时点

为一次检查点分配统一的 `run_id / checkpoint_id / request_id`，在以下边界记录单调时钟：

1. 训练 step 结束与检查点触发；
2. NPU 同步开始/结束；
3. 参数遍历、地址获取、布局生成和 chunk 数组构造；
4. Python → ctypes → C API 进入与返回；
5. 请求环入队、Reactor 取出和首次提交；
6. 每个 chunk 的 HBM→DMA buffer 搬运；
7. SPDK write/read submit 与 completion；
8. 全部数据完成、元数据写入、active slot 切换；
9. 后台 I/O 完成，以及训练真正等待后台 I/O 的时长。

派生指标统一定义为：

- **端到端延迟**：触发至持久化完成；
- **训练阻塞**：训练线程因快照、同步或等待空闲槽而停止的时间；
- **有效带宽**：有效检查点字节数 ÷ 端到端持久化时间；
- **介质带宽**：NVMe 实际提交字节数 ÷ 首次 submit 至最后 completion 时间；
- **软件栈开销**：端到端时间减去不可重叠的设备传输时间；
- **隐藏比例**：后台 I/O 时间中与后续训练重叠的比例；
- **写放大**：NVMe 实际写入字节数 ÷ 有效检查点字节数。

各层计时存在重叠，不能把所有阶段耗时直接相加；报告应同时给出关键路径时间线和
分层累计 CPU 时间。

### 3.4 必要实验

#### E1：设备与内存层次上限

- 顺序读写裸 NVMe，扫描 4 KiB～16 MiB 请求大小和队列深度；
- 测量 Host DRAM memcpy、HBM↔Host ACL memcpy、HBM↔HBM D2D 带宽；
- 记录跨 NUMA 与本地 NUMA 的差异；
- 输出带宽—块大小曲线，为后续结果提供物理上限。

#### E2：路径端到端对比

- 比较 P1～P5 的保存延迟、训练阻塞、有效带宽、CPU 占用和 P95/P99；
- 至少覆盖 1 GiB 合成缓冲、GPT-2 XL 和一个更大模型配置；
- 对同步保存和异步保存分别报告“API 返回时间”和“真正持久化时间”。

#### E3：软件栈分解

- 在固定 4 MiB chunk、固定队列深度下采集 3.3 节全部时间戳；
- 输出瀑布图或关键路径时间线；
- 分别计算框架/编组、同步/快照、Reactor、ACL、SPDK、元数据的占比；
- 使用 CPU profile、上下文切换和系统调用计数验证文件系统路径的控制开销。

#### E4：对象粒度与模型规模敏感性

- 保持总字节数不变，改变参数对象数量，观察逐参数调用和任务编组开销；
- 扫描模型大小、chunk size、pipeline depth、检查点间隔；
- 判断直通收益是否只在大对象顺序写下成立。

#### E5：读取与恢复路径

- 对 P1/P2/P4 对应的读取路径测量加载时间、首参数可用时间和全模型可用时间；
- 覆盖 Host 参数、NPU 参数和混合参数；
- 逐参数比较 dtype、shape、字节内容，并报告恢复后的首步 loss。

### 3.5 完成判据

- 能用同一套数据解释端到端时间与各层关键路径，时间差无法解释的比例低于 5%；
- 所有性能点均通过数据回读或逐参数恢复校验；
- 至少在两种模型规模下说明文件系统旁路和异构内存/存储协同的收益来源；
- 不把不同 SSD、不同计时边界或同步/异步语义的数据画在同一对比柱状图中。

## 4. 工作包二：各设计点消融实验

### 4.1 消融原则

以当前完整 P5 路径为实验组，每次只关闭或替换一个设计点；不能把不同版本、不同
模型或不同磁盘的结果称为消融。所有配置同时报告正确性、性能和资源开销。

### 4.2 消融矩阵

| 编号 | 设计点 | 对照配置 | 实验配置 | 核心指标 | 希望回答的问题 |
|---|---|---|---|---|---|
| A1 | 文件系统旁路 | 内核 FS | SPDK 裸盘 | 延迟、CPU、syscall、P99 | 旁路本身贡献多少 |
| A2 | Host 中转消除 | HBM→Host→NVMe | HBM→DMA→NVMe | 拷贝量、阻塞、带宽 | 少一次中转的真实收益 |
| A3 | 批量任务提交 | 每 chunk 一次 API | 地址/长度/offset 数组批量提交 | Python/C 时间、CPU | 跨语言和提交摊销收益 |
| A4 | 分块流水 | pipeline depth=1 | depth=2/4/8/16 | 带宽、槽等待、P99 | ACL 与 NVMe 能否重叠 |
| A5 | chunk size | 64 KiB～16 MiB | 当前 4 MiB | 带宽、尾块、内存 | 最优粒度及稳定区间 |
| A6 | 单所有者 Reactor | 同步提交或受控旧实现 | Reactor + request ring/FSM | CPU、锁等待、吞吐 | 控制平面是否减少竞争 |
| A7 | FaF 步触发 | Python 同步调用 | 图内计数 + Reactor poller | step time、触发抖动 | 触发卸载贡献多少 |
| A8 | 元数据双槽 | 每次同步单槽写 | A/B 槽 + 原子切换 | 提交时间、故障恢复 | 一致性成本是多少 |
| A9 | 并发快照槽 | 1 个 in-flight | 2/3/4 个槽 | 阻塞、内存、吞吐 | CheckFreq/PCcheck 式并发边界 |
| A10 | NUMA/CPU 绑定 | 不绑定或远端 NUMA | Reactor/内存本地绑定 | CPU、P99、带宽 | 拓扑感知是否必要 |

其中 A6 不直接恢复已归档且存在正确性风险的旧线程实现；应使用受控同步版本或只关闭
请求环重叠的安全配置，避免为了消融重新引入死锁和资源所有权问题。

### 4.3 增量路径内部消融

在增量正确性闭环后增加：

| 编号 | 因素 | 取值 |
|---|---|---|
| D0 | 恢复语义 | S1 相邻步、S2 已持久化状态替换块、S3 残差加法 |
| D1 | 变化块选择 | 全量 Delta、固定 Top-K、自适应 Top-K、阈值选择 |
| D2 | 块大小 | 16K、64K、256K、512K、1M elements（按参数边界切分） |
| D3 | 编码 | FP16、INT8 per-tensor scale、INT8 per-block scale |
| D4 | 参考状态 | 精确 FP32/FP16 `P_persisted`、量化状态+scale、周期性重建 |
| D5 | 误差反馈 | 无残差、Host residual、NPU 图内 residual |
| D6 | FULL 间隔 | 10、25、50、100 steps 或按误差自适应触发 |

## 5. 工作包三：增量检查点探索路径

### 5.1 先做观察实验，不预设 Top-K 一定成立

#### O1：参数变化的空间稀疏性

同时对两个参照量做统计：相邻训练步变化 `P_t-P_{t-1}`，以及相对最近已持久化版本的
累计变化 `P_t-P_persisted`。逐层、逐参数和逐块记录 L1/L2/L∞ norm、非零比例和累计
变化能量—块比例曲线，分别回答 Top-1%、5%、10%、20% 能覆盖多少变化，以及不同层
是否应使用相同阈值。只统计相邻步变化会掩盖长期未写块的累计漂移，不能直接用于选择
恢复协议。

#### O2：时间局部性与“长期饿死”

记录相邻 step 的选中块 Jaccard、块的连续命中长度、距上次持久化的年龄和未保存残差。
重点观察持续小幅变化但长期进不了 Top-K 的块，这类块是历史 100 步误差累积的主要
候选原因。

#### O3：块粒度

扫描块大小，比较选择元数据、padding、并行度、稀疏性和恢复误差。块不能跨参数语义
边界；小参数应单独打包或直接纳入每次 Delta，不能静默忽略。

#### O4：量化与历史状态误差

分别使用精确 FP32/FP16 `P_persisted`、INT8 `P_persisted` 无 scale、INT8
`P_persisted` + per-block scale，区分“写出值量化误差”“选择参考状态失真”和
“未选择块陈旧误差”。测试单步、10/50/100 步链长，而不是只报告一次量化误差；
`INT8` 无 scale 仅作为预期失败的负对照，不能作为候选实现。

#### O5：训练阶段差异

在训练早期、中期和收敛阶段重复 O1～O4，观察更新分布是否随 learning rate 和
optimizer 状态变化。至少包含权重与 optimizer state，避免只凭模型参数推断总检查点。

#### O6：可利用的 NPU 计算窗口

测量 Cube/Vector 利用率和 step 内空闲窗口，分别运行 norm、Top-K、quant、scatter
微基准。判断这些计算能否隐藏在训练空隙中，还是会延长关键路径。

#### O7：端到端成本模型

对每种策略计算：

`总成本 = 图内检测时间 + 持久化时间 + 周期性 FULL 摊销 + 期望恢复时间`

同时报告 HBM 影子状态占用。只减少写入字节但显著增加训练时间或恢复时间的方案不能
视为有效优化。

### 5.2 必须先锁定的增量语义

当前代码和历史实验混用了三种不同含义的 `P_old`，这是判断旧结果时最关键的问题：

| 语义 | 比较对象 | 选择后如何更新参考状态 | 恢复操作 | 主要风险 |
|---|---|---|---|---|
| S1 相邻步 Delta | `P_t-P_{t-1}` | 每步更新所有块 | 加法或替换 | 未选中的小变化不会累计，容易长期丢失 |
| S2 已持久化状态替换块 | `P_t-P_persisted` | 仅在该块持久化 ACK 后更新 | 用 `P_t` 替换对应块 | 需要精确 ACK、双缓冲和 per-block 版本 |
| S3 残差反馈 Delta | `P_t-P_{t-1}+residual` | 每步更新相邻步状态，写出后扣除 residual | 累加量化 Delta | 数值和并发状态最多，重复/漏帧会直接破坏结果 |

R0 首选 **S2 的无损替换块语义**：以最近 FULL 初始化 `P_persisted`，选择相对已落盘
版本变化最大的块，帧内保存该块在 step `t` 的完整 FP16 值；只有收到该帧的持久化 ACK
后，才把对应参考块推进到 `t`。这样帧可幂等重放，重复应用不会二次累加误差，也更容易
做 CPU oracle。S1 只作为负对照；S3 在 S2 闭环后再验证是否值得增加复杂度。

无论采用哪种语义，都必须固定以下不变量：

1. FULL 完成时，所有块的参考状态、恢复基线和 `base_generation` 必须指向同一 step；
2. 块不得跨参数边界，块 ID 必须能唯一映射到参数名、参数内 offset、有效元素数和 dtype；
3. 输出帧记录的是“块当前值”还是“加法 Delta”必须由格式版本显式区分；
4. `READY` 缓冲在 `PERSISTED` 前不可覆写，失败帧不得推进 `P_persisted`；
5. 小参数、optimizer state、loss-scale、RNG 和 data-loader 位置必须明确属于 FULL、每次
   Delta 或独立状态帧，不能因不在大权重块表中而静默丢失；
6. 恢复只接受以同一 FULL generation 为根、step/generation 连续且 checksum 正确的链。

### 5.3 可探索的实现方案

#### 方案 R0：无损块级 Delta 基线

- 采用 S2 替换块语义，保存所有与 `P_persisted` 不同的块；稠密优化器下该集合可能接近
  全量，这是预期基线结果，不人为声称压缩收益；
- 采用 FP16 数据、自描述 Delta frame 和精确 FP16/FP32 `P_persisted`；
- 实现稳定的全局块 ID、参数名、参数内 offset 和 dtype/shape 映射；
- 目标是先闭合 FULL + Delta 恢复语义，为有损方案提供 oracle。

优点是正确性清晰；缺点是 HBM 影子状态和写入缩减可能有限。该方案应最先完成。

#### 方案 R1：自适应 Top-K/阈值 + per-block INT8

- 每层或每参数根据变化分布选择阈值，而非全模型固定比例；
- 写出值和量化参考状态都保存 per-block scale；先保持精确 `P_persisted`，再单独消融
  量化参考状态，禁止同时改变选择策略和参考精度；
- 将小参数、scale、index 和版本信息纳入统一帧；
- 使用字节预算或误差预算控制每步写入量。

这是当前 Top-K 原型最直接的收敛方向，但必须先修复量化历史状态语义。

#### 方案 R2：残差反馈

- 未持久化变化累积到 residual；
- 选择依据使用“本步变化 + residual”；
- 块达到阈值或年龄上限时强制写出，写出后清零对应 residual；
- 对比 Host residual 与 NPU 图内 residual 的性能和 HBM 成本。

该方案针对持续小变化块的长期误差，预期比单纯固定 Top-K 更稳健。

#### 方案 R3：分层热度与周期性 FULL

- 高频变化块高频 Delta，低频变化块降低写入频率；
- 设置最大 Delta 链长、最大块年龄和误差阈值；
- 任一条件达到上限时触发 FULL；
- 恢复时加载最近 FULL，再按序应用带 checksum 和 step ID 的 Delta frame。

该方案利用更新时间局部性，但调度和元数据更复杂，应在 O2 证明存在稳定热度后再做。

#### 方案 R4：HBM→DRAM→NVMe 的分级持久化

- 训练关键路径只完成 HBM 快照或压缩缓冲转移；
- Host DRAM 作为短期暂存，后台合并小 Delta 后写 NVMe；
- 设置 DRAM 容量上限、背压、故障窗口和强制落盘策略。

该方案体现异构存储层次协同，但 DRAM 中尚未落盘的数据不能算可靠检查点。只有在
明确故障模型并量化可靠性窗口后，才可作为正式方案。

#### 方案 R5：两级粗筛与分层块

- 先以较大 super-block 计算低成本摘要，只对超过阈值的区域做细粒度 norm/选择；
- 第一层不得直接丢弃更新，而是维护累计摘要、最大年龄或定期全扫描；
- 与“全模型 norm + 全局 Top-K”比较 HBM 扫描量、漏选率、元数据和图编译复杂度。

该方案只在 5.9.3 证明 norm/Top-K 是主要瓶颈、且 O1 显示变化具有空间聚集性时开展；
若热块快速轮转或粗筛漏选导致误差明显，不继续增加层次。

#### 方案 R6：按训练状态分治的混合检查点

- 权重、Adam 一阶矩、二阶矩、小参数和训练控制状态分别选择 FULL、FP16/INT8 全块、
  稀疏替换块或低频保存；
- 对敏感层/状态保持无损或更高精度，对数据量大且不敏感的状态使用有损编码；
- 以完整训练状态的总物理写量和恢复后继续训练质量评价，不能只报告权重压缩率。

如果 O5 证明权重和 optimizer state 的稀疏性/敏感性显著不同，R6 应优先于强行使用一套
全局 Top-K。直接记录梯度或重放 optimizer update 只有在 RNG、数据顺序和所有优化器
状态能够确定性重建时才作为远期方案，本阶段不纳入主线。

### 5.4 推荐实现顺序与决策门槛

1. **先做 R0。** 若不能完成 100 步 `FULL + Delta` 字节级或数值级恢复，不进入有损优化。
2. **并行完成 O1～O5。** 用观察数据决定固定 Top-K 是否放弃，以及阈值是否分层。
3. **优先比较 R1 与 R2。** R1 验证量化数据缩减，R2解决长期误差；两者可组合。
4. **有明显时间局部性再做 R3/R5。** 若块热度或空间聚集不稳定，不增加调度层次。
5. **状态差异明显时做 R6。** 先证明完整状态上的收益，不以权重结果代替总检查点。
6. **R4 作为扩展路线。** 先完成本地 NVMe 可靠落盘闭环，再研究 DRAM 分级缓存。

增量方案进入正式性能实验的暂定门槛：

- 帧校验、step 连续性、slot 回绕和故障注入全部通过；
- 单步恢复逐参数 NRMSE 中位数不高于 5e-3；
- 100 步链恢复 NRMSE 中位数不高于 1e-2，且无长期未持久化块；
- 恢复后固定批次 loss 相对偏差不高于 1%；
- 平均实际写入量低于 FULL 的 20%；
- 图内增量处理带来的稳定训练 step 开销不高于 10%。

这些是路线筛选门槛，不是论文预设结论；若观察到 loss 对参数误差更敏感，应收紧阈值。

### 5.5 当前实现与历史结果的证据审计

#### 5.5.1 当前可行性判断

截至复核基线 `190e3c0`，应把“研究方向可行”和“当前实现已经可用”分开：

| 能力 | 当前等级 | 依据 | 现阶段允许的表述 |
|---|---|---|---|
| NPU 图内执行差值、归约、Top-K、量化 | 黄 | 历史运行记录表明相关图可编译并产生非零输出，但交叉校验未通过全部门槛 | “算子组合具有原型可执行性” |
| 压缩后的 HBM 缓冲直写 NVMe | 黄 | 原始缓冲曾完成批量写；未证明帧完整、持久化顺序和重启读取 | “数据通路可承载压缩缓冲” |
| 固定 Top-10% 能减少逻辑字节 | 黄 | 理论上 INT8 Top-10% 约为 FP16 FULL 的 5%，但还要计入索引、scale、对齐、FULL 摊销 | “存在数据缩减潜力” |
| 图内结果与 CPU oracle 一致 | 红 | 历史 Top-K 重合率只有 86.8%；当前块布局和参考状态语义仍不一致 | 不能宣称检测正确 |
| `FULL + Delta` 跨进程恢复 | 红 | FaF 写原始三缓冲，`recover()` 只读自描述 frame；现有 T6 不执行恢复 | 不能宣称端到端闭环 |
| 长链误差可控 | 红 | 100 步 CPU 模拟得到高误差，但模拟语义和当前图实现不同，尚无有效对照 | 不能据此肯定或否定 Top-K |
| 训练开销可接受 | 红/黄 | 旧实验出现约 +46.6% 和 +189.3% 开销，实验又存在 NaN、单样本和异构基线问题 | 当前实现尚不满足性能目标，但可继续做降本验证 |
| 崩溃一致性与并发安全 | 红 | 单输出缓冲、ACK 生命周期、ring 回绕和元数据提交仍未闭合 | 不能称为可靠检查点 |

**总判断：**“在 NPU 上先筛选/编码、再经 SPDK 减少写入”的研究假设具有条件可行性；
但当前图上增量实现不具备可恢复、可归因、可发表的完整证据。最可能可落地的近期路线
不是直接修补固定 Top-K 原型，而是先完成 S2/R0，再用真实更新轨迹决定是否加入 INT8、
阈值、残差反馈和图内融合。若 R0 正确但所有有损策略都无法同时满足误差与训练开销，
仍可得到“图上检测可行，但对该稠密 Transformer/优化器不具备端到端收益”的有效结论。

本轮判断来自当前源码、Git 历史中的实验脚本/结果 JSON 和静态交叉核对，未在 Ascend +
SPDK 目标机重新运行；因此下面给出的是“现有证据能支持到哪一级”，重现实验仍按 I0～I7
执行。

| 历史证据 | 可保留的观察 | 主要问题 | 可信度与使用边界 |
|---|---|---|---|
| `results/preliminary/step1/step1_benchmark.json` | GPT-2 XL 稳态 step 约 0.57 s 的量级；训练能运行 | 仅 11 个稳态样本、无 commit；`delta_related_ops` 实际只是按名称筛出的普通训练算子 | 低到中；仅用于估算实验时长，不进入正式对比 |

| 归档 `bench_full.json` | 记录到约 +46.6% 的性能异常信号 | baseline/delta loss 为 NaN，`P_old` 与 quant 最终全零，仍汇总性能 | 无效；只能作为排障线索，不能引用数值 |

历史 100 步“高误差”不应简单归为纯实验错误，也不能直接当作固定 Top-K 已失败的证据。
更准确的结论是：它真实暴露了**参考状态初始化、累计变化语义和长期未选块**会主导结果；
但因为模拟器与当前图实现并非同一算法，数值 `0.760` 不可外推。旧结果中可复用的是实验
问题和失败模式，不是最终数值。

#### 5.5.3 当前代码必须先修正或显式验证的语义缺口

1. `delta_cell.py` 将所有大参数直接串联后只在末尾 padding，但块数按“每参数分别
   padding”计算；这会让实际图中块跨参数边界，和恢复端的参数内 `block_idx` 不一致；
2. 当前图把 INT8 `delta_p_old` 直接 cast 成 FP16，未乘 per-block scale；第一次又从
   全零开始，因此 norm 不是相对最近 FULL 或真实上一版本的变化；
3. 当前图每步重写**所有块**的 `P_old`，历史 CPU 100-step 实验却只推进选中块；前者是
   S1，后者接近但未正确初始化的 S2，两个结果不能互相验证；
4. 输出量化的是选中块的当前值，而名称和部分说明写成 Delta；这可以采用 S2 替换语义，
   但 on-disk header 必须明确标记，恢复端不能误作加法 Delta；
5. 全零块会得到 scale=0，除法路径需规定输出全零且 scale 使用安全哨兵，禁止 NaN/Inf；
6. 小参数尚未进入 FaF 输出；optimizer state、RNG、loss-scale 和数据位置也没有进入链；
7. 单组 HBM 输出缓冲可能在上一帧写盘完成前被下一步覆盖；失败时参考状态也没有可靠
   回滚；
8. FaF 原始三缓冲没有 frame header、块到参数映射、generation 和 checksum，无法被
   当前 `recover()` 消费；
9. Delta ring 与 FULL 槽可能重叠，slot 回绕和重启后的 head/tail 也尚无可信协议。

### 5.6 分层实验流水线：逐层排除“算法错”与“系统错”

任何策略都按 I0～I7 顺序晋级。上层失败时停止做更下层性能优化，以便定位现象来自
选择算法、图执行、帧协议还是存储系统。

| 阶段 | 实验内容 | 对照 oracle | 通过条件 | 失败时首先检查 |
|---|---|---|---|---|
| I0 语义单测 | 小张量、人工更新序列、CPU-only；覆盖 S1/S2/S3 | 逐元素 NumPy 状态机 | 每 step 的选块、参考状态和恢复结果完全符合手算 | 语义定义、初始化、ACK 时序 |
| I1 轨迹回放 | 从真实训练抽取参数/optimizer 更新统计，在 CPU 模拟 R0～R3 | 每 step 精确权重快照 | R0 精确；各有损策略得到稳定误差—字节曲线 | 稀疏性假设、指标、块粒度 |
| I2 图算子等价 | 同一输入同时运行 CPU 与 NPU 图 | I0/I1 的逐块输出 | norm、索引、值、scale、有效长度逐项一致；Top-K tie 允许集合等价 | padding、dtype、溢出、Top-K tie |
| I3 内存闭环 | 图输出进入冻结缓冲，再从缓冲组帧并立即解析 | CPU frame bytes/记录 | generation 对齐；无撕裂；下一步不覆盖未 ACK 缓冲 | Depend/stream 顺序、双缓冲生命周期 |
| I4 文件帧闭环 | frame 写普通文件，再启动新进程恢复 | 精确 FULL + CPU patches | R0 逐参数精确；有损误差与 I1 一致 | frame 格式、块映射、chain 顺序 |
| I5 SPDK 回环 | 同一 frame 经 Host 和 HBM 两条 SPDK 路径写读 | I4 frame checksum | 读取字节一致；边界/非对齐/大帧正确 | 分块、对齐、Host/NPU API、容量 |
| I6 裸盘重启恢复 | FULL + N Delta，关闭并重新初始化后恢复 | 训练时 oracle snapshot | 参数、状态、loss 满足门槛；损坏时明确回退/失败 | 元数据、flush、ring 回绕、故障原子性 |
| I7 端到端训练 | 长训练、后台 I/O、背压和故障注入 | 不检查点连续训练 + FULL-only | 正确性门禁后再比较吞吐、写量、RTO | 资源竞争、快照一致性、成本模型 |

I0/I1 使用三套互相独立的状态：`oracle_current`、`persisted_reference` 和
`recovered_state`，禁止为了省内存让它们共享数组。每个 frame 应可单独重放到两个恢复
副本，验证幂等性；对于 S3 则验证重复帧会被 generation 拒绝，而不是重复累加。

### 5.7 详细实验矩阵

#### 5.7.1 人工更新模式与边界用例

I0 至少覆盖下列模式，每种同时扫块大小、Top-K/阈值和链长：

| 模式 | 构造 | 要验证的失败模式 |
|---|---|---|
| Z0 无变化 | 所有 step 参数不变 | 空帧、零 scale、不得产生 NaN/伪写入 |
| Z1 单块突变 | 仅一个块一次变化 | 块 ID、offset、尾块有效长度 |
| Z2 持续小变 | 同一冷块每步增加小量 | 固定 Top-K 饿死、累计阈值/最大年龄是否生效 |
| Z3 均匀稠密 | 所有块同幅变化 | Top-K tie、固定预算下不可避免的误差下界 |
| Z4 冷热分层 | 10% 块高频大变，90% 低频小变 | 热度策略和残差反馈收益 |
| Z5 热块轮转 | 每步由不同 10% 块变化 | Jaccard 很低时热度缓存是否失效 |
| Z6 突发变化 | 长时间静止后全局大变 | 阈值洪峰、槽容量、自动 FULL |
| Z7 正负抵消 | 相邻步 `+a/-a`，累计接近零 | S1/S2/S3 选择差异和残差定义 |
| Z8 动态范围 | 同块含极大/极小值 | per-tensor 与 per-block quant 误差 |
| Z9 非有限值 | 注入 NaN/Inf | 必须硬失败并拒绝提交，不得量化成静默零 |

参数边界至少包含：小于块、恰好一块、`block_size+1`、多块加尾块、零值参数、常量
LayerNorm 参数、FP16/FP32/BF16、同形不同名、名称较长/含非 ASCII、多参数总长度恰好
4 KiB 对齐与差 1 element。链长取 `0/1/2/10/50/100`；ring 用
`slots-1/slots/slots+1/2*slots+3`，确保至少两次回绕。

#### 5.7.2 真实训练轨迹

使用同一初始权重和同一批次顺序，采集早期、学习率峰值/衰减中段、接近收敛三个窗口。
建议先用小模型完整采样，再对 GPT-2 XL 做分层抽样，避免为观察实验反复搬回全模型。

| 维度 | 最低覆盖 |
|---|---|
| 状态类型 | 权重、Adam 一阶矩、二阶矩、step、loss-scale；若可行再加入 RNG/data position |
| 参数类别 | embedding、attention、MLP、LayerNorm、bias、小参数、共享/tied weight |
| 参照 | `P_t-P_{t-1}` 与 `P_t-P_persisted` 同时统计 |
| block size | 16K、64K、256K、512K、1M elements；不得跨参数边界 |
| 选择预算 | 1%、5%、10%、20%、50%、100%，以及误差阈值和字节预算 |
| 编码 | FP32/FP16 oracle，BF16（若状态原生支持），INT8 per-tensor/per-block，必要时 INT4 仅作探索 |
| FULL 间隔 | 10、25、50、100、500 step，以及按误差/年龄/槽容量触发 |
| 模型 | 小型确定性模型、GPT-2 XL；若资源允许增加另一类结构验证外推性 |

为降低实验数量，先用轨迹回放完成全因子粗筛，再选择 Pareto 前沿上的 3～5 个方案进入
NPU。正式 NPU 实验使用配对/交错顺序，例如 `baseline→candidate→candidate→baseline`，
避免温度、后台负载和缓存随时间漂移。每个策略至少 3 个训练种子；性能点不少于 10 次。

#### 5.7.3 故障、并发与持久化场景

| 场景 | 注入位置 | 正确行为 |
|---|---|---|
| 输出生成中训练进入下一步 | Assign/stream 尚未完成 | 不发布 READY，写盘不得看到混合 generation |
| NVMe 慢于检查点间隔 | 所有缓冲均占用 | 明确 block、合并或触发 FULL；记录丢弃/背压，禁止静默覆盖 |
| 数据写一半进程退出 | frame payload 中间 | 本帧无 commit，恢复选择上一完整 generation |
| payload 完成、header/manifest 未提交 | commit 前 | 本帧不可见，可在启动扫描中回收 |
| manifest 提交但 flush 未完成 | commit/flush 间 | 协议必须保证不会发布；否则判持久化顺序错误 |
| checksum、step 或 base generation 损坏 | 读取/重放 | 硬失败或回退到上一完整链，禁止 warning 后继续 |
| Delta 重复、缺失、乱序 | chain 重放 | S2 可幂等去重；缺失/乱序拒绝恢复 |
| ring 回绕覆盖仍被引用帧 | head 追上 base chain | 先生成新 FULL 或拒绝覆盖 |
| FULL 与 Delta 并发 | 分区/元数据同时更新 | 共享事务代际，恢复只看到完整的一组 |
| 单 rank 失败 | 多 rank prepare 后 | 不发布全局 commit，其他 rank 不得单独成为最新检查点 |

### 5.8 指标、统计和结论边界

恢复误差不能只用“逐参数 NRMSE 中位数”。常量、小方差参数以标准差归一化会被异常
放大，而大参数又可能在简单平均中权重不足。每次至少同时报告：

- 全局和逐参数 `relative_L2 = ||R-O||₂ / (||O||₂+eps)`；
- `update_relative_error = ||R-O||₂ / (||O-FULL_base||₂+eps)`，说明保存了多少真实更新；
- RMSE、最大绝对误差、P50/P95/P99 和最差 10 个参数；
- 按元素加权与按参数等权两种聚合；
- 恢复后固定 batch 的 loss/logits 差、随后 1/10/100 步 loss 轨迹和最终验证指标；
- optimizer state、权重、RNG/data state 分组误差，不能只测权重。

压缩与系统指标统一定义为：

- **逻辑写入比例**：frame 中有效 payload / FULL 有效字节；
- **物理写入比例**：SPDK 实际提交字节 / FULL 实际提交字节；
- **总摊销写入比例**：`(Delta 总物理字节 + 周期性 FULL 字节) / 同期每次 FULL 字节`；
- **变化能量覆盖率**：选中块累计变化能量 / 全部块累计变化能量；
- **陈旧度**：每块距最近持久化 step，报告 mean/P95/max 和超龄块数；
- **写放大**：物理提交字节 / frame 有效字节；
- **训练开销**：候选相对配对 baseline 的 step time 差，并给 bootstrap 95% CI；
- **恢复成本**：RTO、读取字节、应用帧时间、首个可训练 step 时间；
- **资源成本**：额外 HBM/DRAM、Vector/Cube 占用、CPU 核时和 NVMe 容量。

只有同时报告“误差—训练开销—物理写量—恢复时间—额外内存”的 Pareto 曲线，才能
评价方案。单独的 INT8 压缩率、单算子吞吐或 API 返回时间均不足以证明可行性。

### 5.9 观察结果到后续探究的决策表

#### 5.9.1 正确性与数值现象

| 若观察到 | 下一步必须做 | 可以得到的结论 / 路线决策 |
|---|---|---|
| R0 在 I0 就不精确 | 缩到 2 参数 3 块逐 step 手算；检查 FULL 初始化、selected-only ACK 更新、替换/加法标志 | 属于语义/实现错误，不能讨论硬件或压缩 |
| CPU R0 正确、NPU I2 不一致 | 比较 concat 前后、每参数 padding、FP32 norm、Top-K tie、zero-scale；逐层二分定位 | 图布局或数值实现有误；修复后重跑全部策略 |
| norm 近似一致但 Top-K 不一致 | 报告边界处 norm 间隔；用稳定 tie-break、FP32 accumulate 或阈值选择复测 | 若仅等值 tie 且恢复等价可接受；否则 Top-K 数值不稳定 |
| I2 正确、I3 偶发错 | 人为延迟写盘并增加 generation/hash；比较单/双/三缓冲 | 算法可行但输出生命周期错误，必须先完成 ACK 缓冲协议 |
| I4 正确、I5 错 | 同 frame 分别走 Host/NPU SPDK，扫 chunk/对齐/尾块，逐字节找首个差异 | 存储数据面错误，不归因于增量算法 |
| 单步误差低、链长增加近线性/超线性 | 分离 FP16、INT8、Top-K-only、Top-K+residual；缩短 FULL 间隔 | 定位量化累积还是未选块陈旧；决定 R1、R2 或更频繁 FULL |
| FP16 Top-K 也快速漂移 | 扫 K/阈值/最大年龄，画能量覆盖与误差关系 | 主因是选择稀疏化；若 50% 仍不达标，固定 Top-K 不适合该状态 |
| FP16 稳定、INT8 单步即恶化 | 对比 per-tensor/per-block、FP16/FP32 scale、异常动态范围块 | 量化设计不合适；保留 FP16 Delta 或分层精度 |
| 精确参考好、量化参考坏 | 保持写出编码不变，仅替换 `P_persisted` 精度 | 参考状态不可量化或需更高精度/周期重建 |
| 中位误差低但 P95/max 很高 | 定位层/状态/小参数，做敏感参数强制全量或高精度 | 不能以中位数宣称通过；采用分层策略 |
| 参数误差低但恢复 loss 明显异常 | 检查 optimizer、RNG、loss-scale、数据位置、tied weights；跑恢复后多步 | 检查点状态不完整或模型对少数误差敏感 |
| 参数误差高但短期 loss 接近 | 延长到 100/1000 步并测验证集，多 seed | 只能说明短期 loss 不敏感，不能证明恢复正确 |
| 恢复后首步正常、随后发散 | 分组恢复 optimizer moments，比较权重-only/FULL-state | optimizer 或训练辅助状态是主因 |
| 回绕前正确、回绕后错误 | 用小 ring 精确记录 slot generation/head/tail，加入旧 frame 损坏 | ring/manifest 协议错误，暂停性能实验 |

#### 5.9.2 更新分布与算法选择现象

| 若观察到 | 下一步必须做 | 可以得到的结论 / 路线决策 |
|---|---|---|
| Top-10% 长期覆盖 >90% 累计能量且误差稳定 | 跨阶段、seed、optimizer state 复现；比较 5%/10%/20% | Top-K 有数据依据，可进入 R1 性能实现 |
| 更新几乎均匀，能量曲线接近对角线 | 比较 lossless compression、FP16/INT8 全块和降低频率 | 稀疏选块不适合；转向量化全量 Delta 或 I/O 路径优化 |
| 权重稀疏但 optimizer state 稠密 | 分状态采用不同策略，计算完整训练状态总写量 | 只能宣称权重增量收益；总检查点需混合策略 |
| 相邻选中集合 Jaccard 高、热点跨阶段稳定 | 验证热块预取/分层频率，测调度开销 | R3 有实施依据 |
| Jaccard 低、热块快速轮换 | 取消复杂热度缓存，比较简单阈值/残差 | R3 不值得，避免过拟合短窗口 |
| 少数块长期不被选中且 age 长尾 | 加最大年龄、累计阈值、残差反馈三组消融 | 若误差显著改善，长期饿死是主因，优先 R2 |
| 小块误差好但元数据/Top-K 开销大 | 测两级块：大块粗筛、小块细分 | 选择层次化粒度；若仍无收益，选较大块 |
| 大块写量高但计算快 | 扫 64K～256K 并测实际物理写放大 | 在计算与稀疏度之间选 Pareto 点 |
| 训练早期稠密、后期稀疏 | 分阶段预算/FULL 间隔，按 LR 或观测自适应 | 固定全程配置不合理，采用阶段自适应 |
| 各层差异显著 | 每层误差预算或敏感层强制保存，并做简单全局策略对照 | 只有收益超过调度复杂度时采用分层策略 |

#### 5.9.3 性能与系统现象

| 若观察到 | 下一步必须做 | 可以得到的结论 / 路线决策 |
|---|---|---|
| 图内开销主要来自参数 concat/padding | 改为逐参数/分段 kernel，避免构造全模型连续副本；测 HBM 流量 | 当前图组织不可行，算法本身尚未被否定 |
| norm/ReduceSum 主导 | 降采样频率、分层粗筛、融合 kernel、FP32 累积性能消融 | 若仍超过 10%，图上全量扫描不具收益 |
| Top-K 主导且随块数陡增 | 比较阈值、分层 Top-K、近似选择与 CPU 选择 | 阈值能达误差预算则放弃全局 Top-K |
| quant 主导 | 比较只量化选中块、不同块大小和原生低精度路径 | 量化需融合或降低频率，否则保留 FP16 |
| 逻辑字节显著下降，物理字节不降 | 检查 4 KiB 对齐、固定 256 MB 槽写法、尾块和元数据重复写 | 优化帧打包/提交；不能用逻辑压缩率冒充设备收益 |
| NVMe 写很快但训练仍变慢 | 对齐图时间线与缓冲等待，检查 HBM 带宽和同步屏障 | 瓶颈是检测/快照或资源竞争，不是盘 |
| 异步 API 很快但持久化积压增长 | 观察 queue age、in-flight、backpressure 和持久化完成时间 | 只隐藏了延迟且不可持续，不能算吞吐收益 |
| 仅微基准有收益，I7 无吞吐提升 | 代入 FULL 摊销与恢复成本，扩大模型/频率后复测 | 若仍无收益，结论应是端到端不可行 |
| 性能收益只在单一阶段/模型出现 | 增加阶段和第二模型；报告适用条件 | 可形成条件性结论，不外推到所有大模型 |
| R1/R2 达误差但 HBM 额外状态过大 | 比较 Host reference、分层 reference、周期性重建 | 若搬运/内存抵消收益，停止图内全状态路线 |

### 5.10 Go / Pivot / Stop 判据与预期可形成的结论

| 决策 | 判据 | 后续动作 | 可写入论文的结论形态 |
|---|---|---|---|
| Go：继续图上增量 | I0～I6 全过；至少一方案物理写入 <20%、step 开销 <10%、100-step 误差/loss 达门槛 | 扩大模型、训练阶段、多 rank 和故障实验 | 图上筛选在给定条件下带来端到端 Pareto 改善 |
| Pivot A：保留图上量化，放弃稀疏 Top-K | 更新稠密或 K≥50% 才达误差，但 INT8 全块仍能降低写量且开销可控 | 做全块量化 Delta + 周期 FULL | 主要收益来自低精度编码而非空间稀疏 |
| Pivot B：保留检测，改 Host/分级处理 | NPU 图扫描开销高，Host 在冻结快照后可与训练充分重叠 | 比较 HBM→DRAM 后压缩和故障窗口 | 压缩放置位置应由资源竞争决定 |
| Pivot C：只做 FULL I/O 优化 | 权重和 optimizer 更新均稠密，或有损恢复不满足训练质量 | 重点完成 P0～P6、Reactor/FaF 和 FULL 并发路径 | 对稠密 Transformer，增量选择收益不足，直通/异步 FULL 更合适 |
| Stop：当前实现路线终止 | R0 无法闭环，或修正后开销/内存长期显著超过 FULL 且无条件性收益 | 保留负结果和失败分析，不继续堆叠 R3/R4 | 明确图上全模型扫描的适用边界与反例 |

正式结论采用“证据等级”标记：L0 静态推断、L1 单元/模拟、L2 目标机单次观察、L3
可重复正确性实验、L4 跨配置端到端结果。论文主结论至少达到 L3；性能和泛化结论达到
L4。任何失败样本、NaN、零输出或恢复不完整的运行都保留，但只进入故障分析。

## 9. 代码审查整改计划

### 9.1 当前结论与整改边界

当前实现已经具备 Python 后台提交、Reactor 分块状态机、FaF 触发和 Delta 原型，能够
支持路径可行性验证；但在以下门禁完成前，不应把实验结果表述为“训练一致的异步
检查点”“可重启恢复的增量检查点”或“完整的多 rank 检查点”：

1. FULL 与 Delta 都必须冻结某一步的稳定数据，后台 I/O 不得继续读取训练正在修改的
   参数或复用尚未持久化的输出缓冲；
2. FULL、Delta、元数据必须共享唯一磁盘布局，并具有明确的持久化与恢复协议；
3. 后台错误、超时和丢失触发必须传回训练侧，不能以“请求已派发”代替“已持久化”；
4. 正确性测试必须跨进程重启并比较参数、校验和与恢复后 loss，而不是只检查计数器。

整改遵循“先正确、再可恢复、后优化”的顺序。R0 增量路线先使用 FP16 `P_persisted`
建立无损语义基线；INT8 历史状态、Top-K 和残差反馈只在基线通过后比较。

### 9.2 工作包与验收标准

| 编号 | 优先级 | 问题与修改范围 | 主要交付物 | 验收标准 |
|---|---|---|---|---|
| F1 | P0 | FULL 后台线程读取活动 HBM 参数，训练恢复后可能写入混合 step 数据；涉及 `python/direct_checkpoint.py`、训练保存调用点 | 分代快照；双缓冲或等价 D2D 快照；`READY → WRITING → PERSISTED → REUSABLE` 生命周期 | I/O 延迟大于训练 step 时，落盘哈希仍与触发 step 的冻结快照一致；缓冲未收到 ACK 前不可复用 |
| D1 | P0 | Delta 单组输出缓冲会被下一步覆盖；涉及 `python/delta_cell.py`、`src/npu_nvme.c` | Delta 双缓冲/环形缓冲；generation ID；C 侧持久化 ACK | 人为降低 NVMe 速度并连续触发，所有已确认 generation 均可恢复，且无静默覆盖 |
| L1 | P0 | FULL 从盘尾向前分配、Delta 也从盘尾建立 ring，存在重叠风险 | 唯一分区分配器；superblock 中的分区表；4 KiB 对齐与容量断言 | 初始化时证明各区间不重叠；容量不足直接失败；旧格式要求显式重建或迁移 |
| M1 | P0 | A/B 元数据缺少完整校验、代际选择和持久化屏障 | 元数据 CRC、generation、FUA/flush 顺序、双副本回退 | 注入写中断和单副本损坏后，总能选择最新有效副本或明确失败，不能静默初始化空状态 |
| D2 | P0 | Delta 的参考状态语义不一致、INT8 scale 未参与恢复，零 scale、小参数和跨参数分块语义不完整 | S2 + FP16 `P_persisted` 基线；逐参数稳定 ID/padding；零块/小参数处理 | 单步 Delta 与 CPU oracle 逐参数一致；小参数非零更新不丢失；零块不产生 NaN/Inf |
| D3 | P0 | FaF 原始缓冲、Host frame 和 `recover()` 使用的格式未闭环；slot 重启后从 0 开始且回绕元数据可能陈旧 | 唯一自描述 frame；step/generation/checksum；持久化 head/tail；启动扫描与索引重建 | 保存 100 步、发生至少两次回绕、重启后仍能定位正确链；step 不匹配必须硬失败 |
| C1 | P0 | 等待循环、批处理和清理缺少超时/取消，设备异常可能永久阻塞 | 请求 deadline；错误上下文；取消/排空；有界 `close()` | 注入 ACL/SPDK 错误和永不完成请求时，调用在设定时间内失败并释放所有等待者 |
| R1 | P0 | 多 rank 仅 rank 0 提交元数据，缺少全局完成协议；当前未覆盖优化器、RNG 和数据位置 | 每 rank manifest/checksum；两阶段 prepare/commit；完整训练状态 | 任一 rank 失败时不发布全局检查点；成功恢复后下一 step 的 loss/数据顺序与连续训练一致 |
| C2 | P1 | 精确 modulo 轮询在 Reactor 忙时可能漏触发，训练 step 与优化器完成缺少显式先后关系 | 优化器完成后的 READY 发布；pending 队列或明确 latest-wins；漏触发计数 | 快训练、慢 I/O 压测下无静默丢失；每次丢弃都有策略和指标，落盘 step 可追溯 |
| H1 | P1 | Host 参数在注册阶段被过滤，Host 保存分支实际不可达 | Device/Host 参数分类；Host 自有快照；placement 元数据 | CPU、NPU、混合参数三组 round-trip 测试逐字节或逐参数通过 |
| O1 | P1 | task 重注册与多 context 共享全局 Reactor 上下文可能导致悬空引用或串扰 | task generation/refcount；进程级运行时管理器；context 生命周期状态机 | I/O 进行中重注册、双 context 并发和重复关闭均通过内存/并发回归测试 |
| P1 | P1 | 当前是 Python 后台 + Reactor 分块重叠，但 ACL 搬运仍同步，尚不是完整的 NPU-copy/NVMe-write 异步流水 | 先准确标注“两级分块流水”；再评估异步 ACL copy、event query 和多 copy slot | 时间线证明 copy 与 write 的实际重叠；升级后端到端收益显著，否则保留较简单实现 |
| T1 | P0 | 现有 Delta E2E 主要检查计数器或缓冲和值，可能出现假阳性 | 跨进程保存/恢复测试；参数、校验和、loss 校验；负向与故障注入测试 | 测试必须证明数据已持久化；破坏 frame、step 或 metadata 时必须失败；C NPU batch 回环不再留作 TBD |
| I1 | P1 | 计时使用非单调时钟、CSV 易覆盖，缺少排队/同步/Host 路径数据；异步 `save()` 返回值易被误认为成功 | 单调时钟；run/request ID；统一 trace；`DISPATCHED/PERSISTED/FAILED` handle | 任意一次请求可跨 Python/C/ACL/SPDK 关联；结果文件不覆盖；失败能由训练侧观测 |

### 9.3 实施顺序与依赖关系

#### 阶段 A：建立安全基线

1. 先完成 T1 的最小测试骨架，固定当前应通过与应失败的行为；
2. 完成 L1，统一磁盘布局，阻止 FULL/Delta 地址重叠；
3. 完成 F1 和 D1，使 FULL 与 Delta 都具有 step 一致的冻结数据；
4. 完成 C1，使后续测试不会因设备或后台线程异常永久挂起。

阶段出口：单卡 FULL 能在训练继续运行时保存，跨进程重启后与触发 step 的冻结副本一致；
超时和后台错误会使测试失败。

#### 阶段 B：形成可恢复协议

1. 完成 M1，确定 superblock、元数据 A/B 槽的提交与回退顺序；
2. 完成 D2，以 S2 和 FP16 `P_persisted` 建立 Delta CPU oracle；
3. 完成 D3，统一唯一 on-disk frame，补齐 ring head/tail/generation；
4. 将 FULL 与 Delta 的状态提交都接入统一持久化完成语义。

阶段出口：`FULL + N 个 Delta → 关闭进程 → 重新初始化 → 恢复` 全链路通过，slot
回绕、帧损坏和元数据单副本损坏均有确定行为。

#### 阶段 C：控制面与工程可靠性

1. 完成 C2，明确 FaF 的触发顺序、积压策略和漏触发指标；
2. 完成 H1，恢复 Host/混合参数路径；
3. 完成 O1，解决 task/context 所有权和关闭期间并发问题；
4. 完成 I1，统一请求状态、日志和时间线。

阶段出口：慢盘、连续触发、重复初始化/关闭和混合参数压测均无死锁、悬空引用或
静默丢失。

#### 阶段 D：分布式完整性与性能优化

1. 完成 R1，多 rank 两阶段提交并保存完整训练状态；
2. 以 P1 的时间线判断是否实现真正的异步 ACL copy 与多槽流水；
3. 在 R0 正确性基线上实现 INT8 `P_persisted`、残差反馈、自适应阈值和最大块年龄；
4. 最后执行 I/O 路径分析、设计点消融和增量写入量实验。

阶段出口：多 rank 故障恢复可继续训练；所有正式性能结果均建立在对应正确性门禁
已经通过的 commit 上。

### 9.4 正确性与实验门禁

| 门禁 | 必须通过的验证 | 未通过时的限制 |
|---|---|---|
| G0 基础 I/O | Host/NPU × 读/写回环；批量边界、非对齐、容量不足；超时和错误注入 | 不进行任何性能横比 |
| G1 FULL 一致性 | 并发训练下冻结快照哈希一致；跨进程重启逐参数校验；后台失败可见 | 不宣称异步 FULL 正确，不开展 FULL 消融 |
| G2 持久化元数据 | A/B 槽、CRC、generation、flush/FUA、写中断恢复 | 不开展掉电/故障恢复实验 |
| G3 Delta 链 | CPU oracle；小参数/零块；100 步；两次以上回绕；重启与损坏注入 | 不报告实际写入量收益，不比较压缩策略 |
| G4 多 rank | 全 rank prepare/commit；单 rank 失败；优化器/RNG/data state 连续性 | 结论仅限单卡原型，不扩展为分布式检查点 |
| G5 性能证据 | 统一 run ID、环境快照、分层时间线、重复实验与置信区间 | 数据只能作为调试观察，不能作为正式结论 |

每个门禁都应留下：运行命令、配置、commit、设备信息、原始日志、结构化结果和失败
原因。性能优化若改变持久化格式或并发语义，必须重新执行受影响的前置门禁。

### 9.5 建议的提交拆分

为便于回归和消融，整改不合并为一个大提交，建议依赖顺序如下：

1. `测试：建立跨进程恢复与故障注入基线`
2. `磁盘布局：统一 FULL 与 Delta 分区并增加边界校验`
3. `检查点一致性：引入分代快照与双缓冲生命周期`
4. `控制面：增加请求超时、失败传播与有界清理`
5. `元数据：补齐校验、代际与持久化屏障`
6. `增量语义：建立 S2 + FP16 P_persisted 无损恢复基线`
7. `增量协议：统一自描述帧与环形槽元数据`
8. `控制面：补齐 FaF 积压策略与上下文所有权`
9. `分布式恢复：增加多 rank 两阶段提交与完整训练状态`
10. `性能观测：统一分层时间线、请求状态与运行标识`

每个提交至少包含对应单元/集成测试；涉及磁盘格式的提交必须说明是否兼容旧盘，若
不兼容则提供明确的格式版本检查和重新初始化提示。

### 9.6 下一迭代的具体安排

下一迭代只瞄准 G0、G1 和 G2，不同时展开增量压缩策略：

1. **第 1～2 天：**补齐跨进程 FULL 测试、错误注入入口和当前行为基线；
2. **第 3～4 天：**实现统一分区表、容量/重叠断言与格式版本；
3. **第 5～7 天：**实现 FULL 分代快照、双缓冲和持久化 ACK；
4. **第 8 天：**补齐请求超时、错误传播和有界关闭；
5. **第 9～10 天：**完成元数据 CRC/generation/flush 与损坏回退测试；
6. **迭代复盘：**只在 G0～G2 全部通过后，开始 D2/D3 的 R0 Delta 闭环。

该安排的首个可展示成果不是带宽峰值，而是“训练继续执行时生成的 FULL 检查点，
在进程重启后仍精确对应触发 step，并且任一后台故障都可被可靠发现”。它将成为后续
异步流水、消融实验和减少实际写入量论证的共同可信基线。

裁剪及随机 token 可用于 smoke，但必须标记为调试配置，不进入预训练模型更新统计结论。

### 10.2 Q0：兼容性与容量门禁（先做，预计 1–2 日）

- 基于已验收开发分支接入，核对实际 CANN/MindSpore/MindFormers 版本、模型实现提交、
  模型与 tokenizer revision、权重转换脚本和前后哈希。优先保留现有软件栈；确需升级时

- 复用 `experiments/benchmarks/model_compatibility.py` 的探测思想，扩展为配置解析、
  权重加载、前向、反向、Adam 更新及状态枚举。现有探测只调用 AutoConfig，且默认
  Qwen3 路径，不能作为 Qwen2 可训练或可恢复的证明。
- 复用共享模型构造与 `experiments/baselines/repro/runner.py`、`state_bridge.py`，
  排查 GPT-2 特定分支、默认 `vocab_size=50257`、token/label shift、mask、position、

- 固定 manifest，枚举 name/shape/dtype/placement/alias，验证优化器状态已经物化；记录

- 测量峰值 HBM/Host 内存、冻结快照槽位和裸盘预留容量。仅预算估算：若参数为 2 B、

配置解析通过但编译、更新、状态捕获或容量失败时记录 blocker；不直接扩大模型或覆盖旧盘。
若 1.5B 不满足容量条件，先保留 0.5B 正式矩阵，调整排期，不能悄悄改成仅保存权重。

### 10.3 Q1/Q2：最小正确性与性能矩阵（预计 3–5 日）

Q0 后先测 0.5B，全部验收通过后再测 1.5B。每个模型固定：batch 1、128 个训练位置
（若 next-token shift 需要，则输入 129 token）、单卡、Adam 配置、dtype、dropout、
attention kernel、数据样本及 checkpoint interval；context 扩展为 512 只作为后续消融。
预处理真实文本并固定 tokenizer、tokenized batches 与初始 fixture 哈希。同一模型内
三方法共用同一 fixture、保存 step 和 source oracle；跨家族 tokenizer 不同，按 token
预算和实测状态字节分层报告，不强求 token ID 相同。

| 编号 | 最小矩阵 | 验收要求 |
|---|---|---|
| Q1 恢复正确性 | 每模型 × 3 方法 × seeds 41/42/43 | 从固定 fixture 更新 3 步、保存一代；源进程退出，独立恢复并续训 3 步，与该 fixture 的连续训练 oracle 比较 |
| Q2 恢复计时 | 每模型 × 3 方法 × seed 41 × 5 个新进程 | 重用 Q1 有效检查点；另做独立正确性验证，不将全状态哈希混入 state-ready 时间 |
| Q2 保存干扰 | 每模型 × none/Native/ByteCheckpoint/Ours frozen × 3 seeds | 先完成图编译并预热 10 步，正式 30 步、每 10 步保存；每个保存模式完成退出后的恢复与续训门禁 |
| Q3 live（有条件） | 先 0.5B Ours live × 3 seeds，再考虑 1.5B | Q1/Q2 通过且 XL live 共性风险完成诊断后启动；增加 interval 1、慢盘和有界双缓冲压力，检查 generation/ACK/背压 |

两个模型的核心预算为：Q1 共 18 个方法/seed 验证用例，Q2 共 30 个计时新进程与
24 个训练运行；保存、源 oracle 和独立验证还会增加进程数，不以该数字承诺总耗时。
若硬件时间紧，先完成 0.5B 全矩阵，1.5B 先 Q1、再计时；live 和长序列顺延。

恢复门禁同时检查：落盘与装回状态逐字段字节一致、别名恢复、优化器/控制状态完整、
generation/step 精确匹配，以及续训 loss。续训标准在无故障跨进程重复对照后预先固定，
优先沿用现有严格 oracle；任何容差必须有无故障非确定性证据，不能在恢复失败后放宽。
槽位/manifest 损坏或缺少状态字段必须明确失败。完整状态兼容不由成功生成文本判断。

计时统一记录 snapshot/source_read_done/data_durable/generation_committed、训练 step
延迟和 admission wait，以及 metadata/read-deserialize/apply-sync/state-ready；报告实际
物理写量、逻辑状态大小、吞吐、HBM/Host 峰值。恢复仅 5 个样本时报告原始值、均值、
中位数和 min–max，不估 P99；训练三 seed 报告配对变化与不确定性，不预设性能提升。
本小矩阵的重复次数为对历史第 2.2 节通用次数的明确特例。

方法间优先同盘、同 fixture、同保存 step 和相同持久化完成语义；跨物理 SSD 时继续仅作
端点参考。Qwen 和 GPT-2 的总耗时不能直接相除来宣称检查点方法加速。

### 10.4 Q4：增量观测与后续决策（Q1 后，预计 2 日起）

先 Qwen2-0.5B，复用现有观察工具采集 seeds 41/42/43、120 步，窗口
1–20/51–70/101–120，各 seed 60 个观测。1.5B 在轨迹存储与内存预算通过后加入。
扫描 64K/256K 块与 5%/10%/20%/50% 预算，分别统计模型权重、Adam-m、Adam-v 的
adjacent/persisted-reference 覆盖、Jaccard、块年龄、物理对齐字节和误差。模型权重按
embedding/attention/MLP/norm 再分组，避免总体能量掩盖关键类别。

预训练真实文本轨迹用于判断是否有跨模型规律；短窗口结论不外推到收敛质量或所有训练阶段。
该工作包只增加观察证据，仍不启用 Top-K 生产路径。候选只有通过 CPU 恢复 oracle、
分状态误差与资源预算之后，才进入 FULL+Delta 真正持久化和恢复实验。

### 10.5 排期、交付物与停止条件

原 10 日迭代的 P0 基线对齐与 XL 诊断优先级保留。Q0 放入 D1–2 的基线清点阶段；
D3–5 仅在不挤占 XL 诊断资源时做 0.5B 接入与 Q1；D6–10 优先补齐 0.5B Q2。
1.5B 与 Q4 安排后续第 3 周，Q3 live 由正确性门禁决定。串行执行全部新增工作时预计
增加 6–9 个工作日；这是排期估算，编译与适配阻塞需单独记录。协调器优化和增量算法
原型可顺延，不以减少正确性样本换取日历内完成。

计划交付（尚未创建实现）：

- `qwen_compatibility.json`：软件锁定、模型 revision、训练探测、容量与失败原因；
- 共享模型工厂/状态桥适配、0.5B/1.5B 配置、tokenizer/数据 fixture 清单；
- 每模型独立的 checkpoint inventory、逐字段验证、续训 oracle、原始 trace 和结果汇总；
- GPT-2/Qwen 分模型的保存干扰与恢复延迟图，以及分状态类别更新观测表；
- 结论标签：仅兼容 / FULL 已验收 / live 已验收 / 增量仅观察，逐模型标记。

停止条件：训练状态不完整、恢复差异未解释、同方法源/目标 schema 不一致、OOM/容量
不足时停止对应正式矩阵；保留诊断和已通过模型。Qwen 实验失败不阻止已有 GPT-2
基线使用，也不自动触发框架整体迁移。当前更改仅扩展计划，未下载模型、改造代码或运行 Qwen。

## 11. 环境升级与 Qwen3 基准计划（2026-09-09）

### 11.1 本轮目标与基线定位

在保证当前环境可用性的基础上升级环境，检查 Qwen3-8B 的可用性；如果通过对应训练、
检查点和恢复验收，以后的实验将采用 Qwen3-8B 作为基准实验的一部分。
此处“可用”必须标明推理、权重 I/O、全状态训练、异步快照或分布式恢复的具体范围。
只能推理或读写权重时，先纳入权重 I/O 子矩阵，不能标为完整训练检查点基准。

历史记录为 910B3、每卡 64 GiB HBM、MindSpore 2.5.0、MindFormers 1.3.2、
CANN 7.5.0.1.129；2026-08-25 的 `/models/Qwen3-8B` AutoConfig 探测失败。
这些是已保存证据，执行前重新核对服务器实际版本与设备占用，不能当作当前在线状态。
旧探测只证明该加载入口失败，不代表硬件不支持 Qwen3。

GPT-2 XL 保留为历史结果可比、故障复现和环境回归模型，新增主结果应覆盖现代模型。
2025 年仍有 GPT-2 XL 科研论文，例如 [COLING 2025 的可解释性研究](https://aclanthology.org/2025.coling-main.677/)；
近期也有使用 Qwen3 的 [EMNLP 2025 论文](https://aclanthology.org/2025.emnlp-main.364/)。
这些实例不能构成使用率调查，不据此声称 GPT-2 XL 的使用比例或下降幅度。
本项目更换主基准的依据是架构覆盖、状态规模与可复现性，而非模型热度排名。

### 11.2 E0–E3：保留旧环境的升级流程

| 工作包 | 工作与交付物 | 验收出口 |
|---|---|---|
| E0 现状固化 | 记录 Python 包锁、源码/子模块、CANN/toolkit/kernels、驱动固件、环境变量、ACL/SPDK 动态库实际解析路径、hugepage/NVMe 绑定、设备及磁盘布局；保存旧环境启动命令、构建产物和 fixture | 原环境可独立启动，GPT-2 原生训练和 FULL 保存→新进程恢复→续训通过，故障/超时代表用例有记录 |
| E1 版本选择 | 按官方 Qwen3 模型支持与版本匹配表选择一个固定发行组合，记录 MindSpore/MindFormers/CANN/驱动/Python/910B 支持依据；先验证现有驱动能否支持候选组合 | 输出版本决策表；不将任意最新包混装，不默认仅升级 pip 包即可 |
| E2 隔离安装与适配 | 新建独立环境或容器、独立代码 worktree、独立 build/run 目录；并存 toolkit 使用显式路径，不覆盖全局默认环境；重新编译候选 ACL/SPDK 桥并核对 ABI、设备指针提取与训练状态枚举 | 旧环境文件与库未被替换；新环境四条 Host/NPU I/O 回环、错误传播和 GPT-2 训练/恢复通过 |
| E3 切换与回退演练 | 顺序执行旧→新→旧环境验证，记录各环境实际加载库及相同 fixture 的结果；新环境通过后仅将其设为新增 Qwen 实验入口 | 两套入口均可用；失败可以恢复旧入口，无裸盘格式或旧检查点的隐式迁移 |

容器/虚拟环境不能隔离宿主驱动和固件。若候选版本强制要求宿主升级，先形成完整的
兼容性清单、维护窗口及回退步骤，并确认旧栈在新驱动上仍有可验证支持；不能保证时，
转到另一节点或延后该组合，不在唯一可用节点上直接替换。驱动/固件变更另行列为明确
运维动作，本次计划更新不执行安装或系统变更。

官方入口：[Qwen3 模型支持表](https://www.mindspore.cn/mindformers/docs/zh-CN/r1.8.0/introduction/models.html)、
[安装指南](https://www.mindspore.cn/mindformers/docs/zh-CN/r1.8.0/installation.html)。
这些页面用于确认已有支持路线，不在尚未核实宿主兼容性时直接锁定 1.8.0 或最新版本。
升级后所有方法在同一候选环境内重新测量，不能把新 Qwen 数据与旧 GPT-2 时间直接做加速比。

### 11.3 单卡模型组合与容量门禁

| 模型 | 定位 | 决策 |
|---|---|---|
| GPT-2 / GPT-2 XL | 快速回归、已有故障与历史结果对照 | 保留；不再作为唯一现代模型证据 |
| Qwen3-0.6B | 新环境编译、状态桥和恢复的低成本 smoke | 可选，仅在 1.7B 调试代价明显过高时使用 |
| Qwen3-1.7B | 单卡全参数训练与完整检查点主候选 | 优先通过 Q0/Q1，再开展三方法正式矩阵 |
| Qwen3-4B | 单卡容量与快照压力候选 | 测量优化器、梯度、激活和快照峰值后决定；不保证 64 GiB 中能放下异步完整快照 |
| Qwen3-8B | 重点可用性评估；通过后纳入常规基准 | 单卡权重 I/O 与完整训练分开验收；全状态训练可能需要分片或 Host 卸载 |
| Llama-3.2-3B | 可选第二模型家族，检查架构外推 | Qwen 主矩阵后再选；先核对训练支持、模型获取条件、容量和恢复，不同时铺开全部模型 |
| Qwen2-0.5B/1.5B | 旧环境备选 | 仅升级阻塞或需旧栈对照时启用，第 10 节完整矩阵不再默认必做 |

容量预算按 2 B 参数 + 8 B Adam m/v = 10 B/参数估算，有 FP32 master weights 则
为 14 B/参数。按标称规模，1.7B 约 17–23.8 GB、4B 约 40–56 GB；官方 Qwen3-8B
为 8.2B 参数，对应约 82–114.8 GB。这是十进制静态状态预算，不含梯度、激活、框架
工作区和快照副本；实际以唯一存储 manifest、精度配置及实测峰值为准。
完整冻结快照可能再增加一份状态：不能凭权重能加载就判断 4B/8B 异步训练可用。

8B 单卡 BF16 权重约 16.4 GB，可先做权重保存/恢复压力验证；全参数 Adam 状态不能
按上述配置全部常驻单卡 64 GiB HBM。普通数据并行每卡复制状态不能解决此问题。
如采用状态分片，单独列入多卡基准；如采用 Host 卸载，则明确为单卡+Host 卸载基准，
各方法固定卸载策略并计入 Host 内存、额外搬运和训练开销。不得用 LoRA 或少保存状态
的方式冒充全参数检查点。重新核对裸盘容量与多代际布局，不能沿用小模型槽位大小。

模型配置与初始化权重分别锁定 repository/revision。选择 Base 用于持续训练时，明确
记录具体 Base 仓库；使用 `Qwen/Qwen3-8B` 时按其实际预训练+后训练权重标记，不改名为 Base。
架构相同不等于同一初始状态；同模型三方法必须复用相同 fixture/step/source oracle。
输入先固定 batch 1、128 个训练位置，再按资源预算扩到 512；吞吐压力通过规模、频率和
序列长度分别控制，避免多个因素同时变化。

模型来源：[Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B)、
[Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B)、
[Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B)、
[Llama-3.2-3B](https://huggingface.co/meta-llama/Llama-3.2-3B)。模型卡存在不代表
当前候选 MindFormers 版本的全参数训练和本项目 checkpoint bridge 已验收。

### 11.4 验收、排期与纳入后续实验的条件

第一周：E0/E1 固化旧环境与选择组合，E2/E3 安装隔离环境、GPT-2 回归与回退演练；
保留 XL live 原严格续训偏差的诊断工作，不因更换模型把历史失败标为解决。
第二周：优先进行 Qwen3-8B 配置/权重加载与容量探测，并完成 Qwen3-1.7B 的训练和
Q1 新进程恢复；8B 具备条件时验证权重 I/O，再为完整训练选择卸载/分片方案。
第三周起：通过的模型进入 Q2 三方法正式计时；4B、第二家族和 Q4 观测按容量和预算
顺序加入。版本迁移或 8B 分片/卸载是独立工作包，不能沿用旧方案 6–9 日为全部工作承诺。

复用第 10 节 Q0–Q4 协议，但替换模型维度，不叠加全部历史模型矩阵。每个通过的
完整训练模型，Q1 为三方法 × 三 seeds；恢复计时为三方法 × 五个新进程；保存干扰为
none/Native/ByteCheckpoint/Ours frozen × 三 seeds。先 frozen/serial，live 需单独通过
慢盘、缓冲复用、ACK 与严格续训验收。恢复哈希与计时分进程，保留跨物理盘限制。

交付物：`environment_upgrade_inventory`、候选版本与兼容性决策、两套环境启动入口、
回归/回退报告、逐模型 `model_acceptance`、容量峰值与状态 manifest、原始计时和恢复证据。
每模型明确标记 config/load/train/weights-roundtrip/full-restart/live 各阶段结果。

Qwen3-8B 在相应范围通过后，后续同类正式实验默认包含它；若仅权重路径通过，后续
权重 I/O 矩阵纳入，完整训练矩阵仍使用已通过的 1.7B 等模型，并保留 8B 阻塞项。
任何升级回归失败先恢复旧环境；实验失败保留原始日志，不能删除 GPT-2 历史基准来回避。
本次仅更新计划，未执行环境升级或新模型实验。
